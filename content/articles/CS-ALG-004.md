## 0. 한눈에 보기 (입문)

### 한 줄 요약
**재귀**는 "문제를 같은 모양의 더 작은 문제로 줄여서 푸는" 방법이고, **분할 정복**은 문제를 여러 조각으로 나눠 각각 풀고 합치는 재귀의 대표적 전략이다. 정렬, 트리·그래프 탐색, 중첩된 데이터 처리가 모두 이 방식으로 돌아간다.

### 쉬운 설명
러시아 인형(마트료시카)을 떠올리자. 인형을 열면 더 작은 인형이 있고, 또 열면 더 작은 인형이 있다. 가장 작은 인형(더 이상 안 열림)에 도착하면 멈춘다.

재귀 함수도 같다.
1. **멈추는 조건:** "가장 작은 인형이면 끝."
2. **줄이기:** "아니면 열어서 안쪽 인형에게 같은 일을 시킨다."

분할 정복의 예: 카드 100장을 정렬하려면 50장씩 둘로 나눠 각각 정렬하고(같은 방법으로 또 나눠서), 정렬된 두 묶음을 앞에서부터 비교하며 합친다. 한 장짜리 묶음은 이미 정렬된 것이니 거기서 멈춘다. 이것이 **병합 정렬**이다.

### 내 프로젝트에서는
- **이 학습 사이트의 순환 탐지가 재귀다.** 선행 관계에 순환(A → B → A)이 있는지 검사하는 `detectCycles`(`scripts/lib.mjs`)는 개념 하나를 방문하면서 그 개념의 다음 개념들을 **같은 함수로 다시** 방문하는 깊이 우선 탐색(DFS)이다. 방문 중인 개념을 다시 만나면 순환이다(MATH-GRAPH-001). 이 검사가 매일 예약 실행의 검증 단계에서 돌아간다.
- **DeepVi·Preflight에서 재귀 알고리즘을 직접 구현한 기록은 없다.** 다만 Preflight가 다룬 xlsx 파일은 XML이 중첩된 구조라(CS-DATA-001), 이런 파일을 읽는 파서는 내부적으로 재귀 구조를 처리한다.

### 먼저 알면 좋은 것
- 알고리즘과 자료구조(CS-ALG-001): 배열, 트리
- Big-O와 시간·공간복잡도(CS-ALG-002): $O(n \log n)$, $O(2^n)$

## 1. 핵심 요약

- **재귀의 두 요소:** 기저 사례(멈추는 조건) + 재귀 단계(더 작은 문제로 같은 함수 호출).
- **호출 스택:** 호출마다 스택에 한 칸씩 쌓이고, 기저 사례부터 차례로 돌아온다. 깊이가 너무 깊으면 스택 넘침(Python 기본 한계 약 1,000).
- **분할 정복:** 나누기 → 각각 풀기(재귀) → 합치기. 병합 정렬, 퀵 정렬, 이진 탐색.
- **점화식:** 병합 정렬 $T(n) = 2T(n/2) + O(n)$ → $O(n \log n)$.
- **겹치는 부분 문제:** 단순 재귀 피보나치는 같은 계산을 반복해 $O(2^n)$급. 메모이제이션(결과 기억)이나 동적계획법(CS-ALG-003)으로 $O(n)$.
- **재귀 ↔ 반복:** 모든 재귀는 명시적 스택을 쓰는 반복문으로 바꿀 수 있다. 깊이가 클 때 유용.

## 2. 개념과 등장 배경

재귀적 정의는 수학에서 오래되었다(자연수의 귀납적 정의, 피보나치 수열). 1930년대 괴델, 처치, 클리니가 "재귀 함수"로 계산 가능성을 정의했고, 1958년 존 매카시(John McCarthy)의 LISP가 재귀를 프로그래밍의 기본 도구로 만들었다. 1960년 ALGOL 60이 재귀 호출을 지원하면서 대부분의 언어로 퍼졌다.

분할 정복의 대표인 **병합 정렬**은 1945년 존 폰 노이만(John von Neumann)이 고안했고, 1960년 토니 호어(Tony Hoare)가 **퀵 정렬**을 발표했다. 1962년 카라추바의 곱셈 알고리즘, 1965년 쿨리-튜키의 고속 푸리에 변환(FFT)은 분할 정복이 계산량을 극적으로 줄일 수 있음을 보였다. 비교 기반 정렬은 최악의 경우 $\Omega(n \log n)$보다 빠를 수 없다는 하한도 알려져 있다.

## 3. 직관적 설명 및 기초 이론

### 호출 스택 따라가기: 계승(팩토리얼)

```javascript
function fact(n) {
  if (n <= 1) return 1;      // 기저 사례
  return n * fact(n - 1);    // 더 작은 문제
}
```

`fact(4)`:
```text
fact(4) = 4 × fact(3)
               fact(3) = 3 × fact(2)
                              fact(2) = 2 × fact(1)
                                             fact(1) = 1   ← 멈춤
                              fact(2) = 2 × 1 = 2
               fact(3) = 3 × 2 = 6
fact(4) = 4 × 6 = 24
```

내려갈 때는 스택에 쌓이고, 기저 사례에서 돌아오며 계산이 완성된다.

### 분할 정복의 세 단계

| 단계 | 병합 정렬 | 이진 탐색 |
|---|---|---|
| 나누기 | 배열을 반으로 | 가운데 값과 비교해 한쪽 절반만 |
| 풀기 | 두 절반을 각각 재귀 정렬 | 남은 절반에서 재귀 탐색 |
| 합치기 | 정렬된 두 절반을 병합 | 없음 |
| 복잡도 | $O(n \log n)$ | $O(\log n)$ |

## 4. 엄밀한 정의와 작동 원리

### 병합 정렬의 점화식

길이 $n$을 정렬하는 시간 $T(n)$은 절반 두 개를 정렬하는 시간 + 합치는 시간($n$에 비례):

$$
T(n) = 2T\!\left(\frac{n}{2}\right) + cn, \qquad T(1) = c
$$

재귀 나무로 보면 깊이는 $\log_2 n$단계이고, 각 단계에서 합치는 일의 총량이 $cn$이므로

$$
T(n) = cn \log_2 n + cn = O(n \log n)
$$

일반적인 형태 $T(n) = aT(n/b) + f(n)$은 "마스터 정리"로 정리된다.

### 겹치는 부분 문제와 메모이제이션

$$
F(n) = F(n-1) + F(n-2), \quad F(0) = 0,\ F(1) = 1
$$

단순 재귀는 $F(n-2)$를 $F(n-1)$ 안에서 또 계산하는 식으로 같은 값을 반복 계산해 호출 수가 지수적으로 는다. 한 번 계산한 $F(k)$를 표에 저장해 두면(메모이제이션) 각 값을 한 번씩만 계산해 $O(n)$이다. 겹치는 부분 문제 + 최적 부분 구조가 동적계획법의 조건이다(CS-ALG-003).

### 재귀 깊이

재귀 깊이 $d$만큼 스택 공간 $O(d)$가 필요하다. 병합 정렬은 깊이 $\log n$이라 문제없지만, 연결 리스트를 한 칸씩 재귀로 따라가면 깊이 $n$이라 긴 데이터에서 스택이 넘친다. 이럴 때는 반복문 + 명시적 스택으로 바꾼다.

## 5. 수식 및 기호 설명

| 기호 | 뜻 |
|---|---|
| $T(n)$ | 크기 $n$ 문제의 실행 시간 |
| $T(n/2)$ | 절반 크기 문제의 시간 |
| $cn$ | 합치기에 드는 시간($n$에 비례) |
| $\log_2 n$ | 반으로 나누는 단계 수 |
| $F(n)$ | 피보나치 수 |
| $O(\cdot)$, $\Omega(\cdot)$ | 상한, 하한(CS-ALG-002) |

## 6. 단계별 계산 또는 동작 예제

### 예제 1. 병합 정렬

[5, 2, 8, 1, 9, 3, 7, 4]

```text
나누기:  [5 2 8 1] [9 3 7 4]
         [5 2] [8 1] [9 3] [7 4]
         [5][2] [8][1] [9][3] [7][4]
합치기:  [2 5] [1 8] [3 9] [4 7]
         [1 2 5 8]   [3 4 7 9]
         [1 2 3 4 5 7 8 9]
```

마지막 병합: 1(왼쪽) vs 3 → 1, 2 vs 3 → 2, 5 vs 3 → 3, 5 vs 4 → 4, 5 vs 7 → 5, 8 vs 7 → 7, 8 vs 9 → 8, 남은 9. 비교 7번.

전체 비교 횟수는 17번(python으로 실행해 셈)이고, 상한 $n \log_2 n = 8 \times 3 = 24$ 이내다.

### 예제 2. 단순 재귀 피보나치의 폭발

$F(20) = 6765$를 단순 재귀로 계산하면 함수 호출이 **21,891번** 일어난다(python으로 셈). 메모이제이션을 쓰면 $F(0)$~$F(20)$을 한 번씩, 21번 계산하면 된다. 호출 수가 약 1,000배 차이다. $n$이 40이면 단순 재귀는 수억 번을 넘는다.

### 예제 3. 규모 감각

데이터 100만 개를 정렬할 때:
- $O(n \log n)$ 병합 정렬: 약 $10^6 \times 20 = 2 \times 10^7$번 비교 수준
- $O(n^2)$ 단순 정렬(삽입 정렬 최악): 약 $\tfrac{1}{2} \times 10^{12} = 5 \times 10^{11}$번

2만 5천 배 차이다. 실제로는 DB의 `ORDER BY`나 언어의 내장 정렬이 효율적인 알고리즘을 쓰므로 직접 구현할 일은 드물지만, "반복문 안에서 반복문으로 비교"하는 코드가 왜 느린지 이해하는 기준이 된다(CS-ALG-002).

### 예제 4. 깊이 우선 탐색으로 순환 찾기

이 사이트의 `detectCycles`를 단순화하면:

```javascript
function visit(u) {
  color[u] = '방문 중';
  for (const v of next[u]) {
    if (color[v] === '방문 중') 순환발견(u, v);      // 지금 경로에 이미 있음
    else if (color[v] === '미방문') visit(v);      // 같은 함수로 더 깊이
  }
  color[u] = '완료';
}
```

선행 관계 "집합과 논리 → 그래프 이론 → 온톨로지"에서 `visit(집합과 논리)`는 `visit(그래프 이론)`을, 그것은 `visit(온톨로지)`를 부른다. 온톨로지에서 나가는 화살표가 "집합과 논리"를 가리키면, 그 개념이 아직 "방문 중"이라 순환으로 잡힌다. 개념이 수십 개라 깊이가 문제되지 않지만, 수십만 개 정점의 그래프라면 반복문 + 스택으로 바꾸는 것이 안전하다.

## 7. 시각화와 해석

재귀 호출은 **호출 나무**로 그린다. 병합 정렬은 높이 $\log_2 n$의 균형 잡힌 나무, 단순 피보나치는 같은 가지가 여러 번 반복되는 무성한 나무다. 같은 숫자가 나무 여러 곳에 보이면 "겹치는 부분 문제 → 메모이제이션 대상"이라는 신호다. 예제 1의 나누기·합치기 그림은 위에서 아래로 갈라졌다 다시 모이는 모양이라 분할 정복의 구조가 그대로 보인다.

## 8. 기술 비교 및 선택 기준

| 상황 | 권장 |
|---|---|
| 트리·중첩 구조(폴더, XML, JSON) 처리 | 재귀가 자연스러움(깊이가 얕을 때) |
| 깊이가 수천 이상일 수 있음 | 반복문 + 명시적 스택/큐 |
| 같은 부분 문제 반복 | 메모이제이션 또는 동적계획법 |
| 정렬 | 언어·DB 내장 정렬(대개 $O(n \log n)$ 계열) |
| 최단 단계 탐색 | 재귀 DFS 대신 큐 기반 BFS(MATH-GRAPH-001) |

## 9. 실무 사례

- **폴더 크기 계산:** 폴더 크기 = 파일 크기 합 + 하위 폴더 크기(재귀) 합.
- **조직도·BOM(부품 구성표) 펼치기:** "이 제품에 들어가는 모든 부품"을 재귀로 찾는다. DB에서는 `WITH RECURSIVE`(MATH-GRAPH-001 Q4).
- **대용량 정렬:** 메모리에 다 안 들어가는 데이터를 조각으로 나눠 정렬한 뒤 병합(외부 정렬).
- **JSON 정리:** 중첩된 객체의 모든 키를 재귀로 돌며 이름을 바꾸거나 민감 정보를 가린다.

## 10. 기존 프로젝트와의 연결

아래 사실은 포트폴리오·저장소 원문(`content/profile.json`)과 이 사이트의 코드에서 옮긴 것이다.

- **이 학습 사이트 — 순환 탐지:** `scripts/lib.mjs`의 `detectCycles`가 재귀 깊이 우선 탐색으로 선행 관계 순환을 찾고, 검증 단계에서 순환이 있으면 저장을 막는다(예제 4). 다음 주제 고르기(next-candidates)의 선행 개념 거슬러 올라가기(`walkUp`)도 재귀다.
- **Preflight — 중첩 파일:** ExcelJS·SheetJS가 읽지 못한 비표준 xlsx를 정규화하는 모듈을 만들었다(포트폴리오 기재). xlsx 내부의 XML은 중첩 구조라 파서가 재귀적으로 처리한다. 정규화 모듈의 구현 방식은 기재가 없다.
- **DeepVi:** 재귀 알고리즘을 직접 쓴 기록은 없다. 기업·뉴스 목록을 정렬해 보여 주는 화면(`sort_values`)은 pandas 내장 정렬을 쓴다.

## 11. 가정·한계·흔한 오해·트레이드오프

- **오해: 재귀는 항상 느리다.** 병합 정렬처럼 효율적인 재귀도 많다. 느린 것은 겹치는 부분 문제를 반복 계산하는 경우다.
- **오해: 재귀가 더 우아하니 항상 쓴다.** 깊이가 크면 스택 넘침, 함수 호출 비용이 문제다.
- **기저 사례 실수:** `n <= 1` 대신 `n == 1`로 쓰면 0이나 음수 입력에서 끝없이 내려간다. 경계값 시험이 필요하다(SE-TEST-001).
- **꼬리 재귀 최적화:** 일부 언어만 지원한다. Python과 대부분의 JavaScript 엔진은 기대하지 않는 것이 안전하다(확인 필요).
- **메모이제이션의 메모리:** 저장할 부분 문제가 많으면 메모리를 많이 쓴다.

## 12. 이해 확인 및 면접 질문

<details class="qa" data-type="concept"><summary>Q1. 병합 정렬이 $O(n \log n)$인 이유를 한 문장으로 설명하라.</summary>

**정답.** 배열을 반으로 나누는 단계가 $\log_2 n$번이고, 각 단계에서 모든 원소를 한 번씩 합치는 데 $O(n)$이 들기 때문이다.

**해설.** 점화식 $T(n) = 2T(n/2) + cn$의 재귀 나무에서 단계 수 × 단계당 일.

</details>

<details class="qa" data-type="concept"><summary>Q2. 이진 탐색으로 정렬된 100만 개에서 값을 찾을 때 최대 비교 횟수는 대략?</summary>

**정답.** 약 20번($\log_2 10^6 \approx 19.9$).

**해설.** 매번 후보를 절반으로 줄이는 분할 정복이다.

</details>

<details class="qa" data-type="judgment"><summary>Q3. 조직도(직원-상사)를 재귀 함수로 펼치는 코드가 운영 중 가끔 무한히 돌다가 죽는다. 원인과 대책은?</summary>

**정답.** 데이터에 순환(A의 상사가 B, B의 상사가 A)이 있어 기저 사례에 도달하지 못한다. 방문한 직원을 기록해 다시 만나면 멈추고(순환 보고), 깊이 한도를 둔다. 데이터 쪽에서도 순환을 막는 검증을 둔다.

**해설.** 이 사이트의 `detectCycles`가 "방문 중" 표시로 순환을 잡는 것과 같은 방어다.

</details>

<details class="qa" data-type="applied"><summary>Q4. 중첩 깊이를 알 수 없는 JSON 설정 파일에서 "password"라는 키를 모두 찾아 가리려 한다. 어떻게 구현하겠는가?</summary>

**정답.** 값이 객체면 각 키를 돌며 "password"면 가리고 나머지 값에 같은 함수를 재귀 호출하고, 배열이면 각 원소에 재귀 호출, 그 외 값은 그대로 둔다. 깊이가 매우 클 수 있으면 스택을 쓰는 반복문으로 구현하고, 깊이 한도를 둔다.

**해설.** 중첩 구조는 재귀의 전형적 대상이다. 기저 사례는 "객체도 배열도 아닌 값"이다.

</details>
