## 0. 한눈에 보기 (입문)

### 한 줄 요약
**셸**은 컴퓨터에게 글자로 명령하는 창구다. 마우스로 하던 일(파일 복사, 프로그램 실행)을 명령어로 하면 **기록되고, 반복할 수 있고, 자동화**할 수 있다. 서버 대부분이 화면 없는 리눅스라, 개발·데이터 일을 하면 피할 수 없는 기본기다.

### 쉬운 설명
식당으로 비유하면 이렇다.
- **운영체제(리눅스, 윈도우):** 주방 전체. 재료(파일), 조리 기구(CPU, 메모리), 요리사들(프로그램)을 관리한다.
- **셸(bash, PowerShell):** 주문을 받아 주방에 전달하는 직원. "이 파일을 저기로 복사해"라는 글자 주문을 운영체제가 알아듣는 일로 바꾼다.
- **터미널:** 주문서를 쓰는 창(검은 화면).

명령어 한 줄은 보통 이렇게 생겼다.

```
cp  -r  reports/  backup/
명령  옵션  대상1     대상2
```

"reports 폴더를 통째로(-r) backup 폴더로 복사하라"는 뜻이다.

셸의 진짜 힘은 **작은 명령을 이어 붙이는 것**이다. `|`(파이프)는 앞 명령의 출력을 뒤 명령의 입력으로 넘긴다. 예를 들어 `cat 접속기록.log | grep 오류 | wc -l`은 "기록 파일을 읽어서 → '오류'가 든 줄만 골라 → 줄 수를 센다"이다. 엑셀로 하면 파일을 열고 필터를 걸고 개수를 봐야 하는 일을 한 줄로, 매일 똑같이 반복할 수 있다.

그리고 명령을 파일에 적어 두면 **스크립트**가 된다. 누가 실행해도, 몇 번을 실행해도 같은 순서로 같은 일을 한다.

### 내 프로젝트에서는
- **Preflight — PowerShell 운영 스크립트:** 클라우드 없이 사내 서버에서 운영하고, **설치·백업·복원을 PowerShell 스크립트로** 정리했다. 또 개발을 거치지 않은 변경은 **배포 스크립트가 거부**하게 했다(포트폴리오 기재). 전담 운영 인력이 없는 현장에서 "누가 해도 같은 결과"가 나오게 하는 것이 셸 스크립트의 핵심 가치다. PowerShell은 윈도우의 셸이고, 이 설명집의 bash와 개념(명령, 파이프, 종료 코드, 스크립트)이 같다(8절).
- **DeepVi:** 저장소에 `Procfile`이 있다(저장소 직접 확인). Procfile은 "이 앱을 실행하는 명령어 한 줄"을 적어 두는 파일로, 클라우드 플랫폼이 이 명령을 셸에서 실행해 앱을 띄운다. 상시 운영 배포 서버는 열지 않았다(포트폴리오 기재).
- **STT 평가:** Whisper, NeMo, Riva, vLLM 같은 도구는 보통 리눅스 GPU 서버에서 명령줄로 실행한다. 포트폴리오에 실행 환경의 세부 기록은 없다.

### 먼저 알면 좋은 것
- 파일 형식과 문자 인코딩(CS-DATA-001): 텍스트 파일, 줄바꿈, UTF-8
- 배포와 환경 분리(OPS-DEPLOY-001): 스크립트로 배포·백업하는 이유

## 1. 핵심 요약

- **구성:** 커널(운영체제 핵심) ← 셸(명령 해석) ← 터미널(입출력 창). 리눅스의 기본 셸은 보통 bash, 윈도우는 PowerShell.
- **명령 구조:** `명령 [옵션] [대상]`. 도움말은 `명령 --help`나 `man 명령`.
- **경로:** `/`부터 시작하면 절대 경로, 아니면 현재 위치(`pwd`) 기준 상대 경로. `~`는 내 홈 폴더, `.`은 현재, `..`은 상위.
- **권한:** 소유자·그룹·기타 사용자 각각 읽기(r=4)·쓰기(w=2)·실행(x=1). `755` = `rwxr-xr-x`.
- **조합:** 파이프 `|`, 출력 저장 `>`(덮어쓰기)·`>>`(이어쓰기), 입력 `<`, 오류 출력 `2>`.
- **종료 코드:** 0이면 성공, 0이 아니면 실패. 스크립트는 이것으로 다음 단계를 진행할지 정한다.
- **환경 변수:** `PATH`(명령을 찾는 폴더 목록), 설정값·비밀값 전달. 비밀값을 스크립트 파일에 직접 쓰지 않는다.
- **안전한 스크립트:** 실패하면 멈추기(`set -euo pipefail`), 실행 전 확인, 기록 남기기, 되돌릴 길 준비.

## 2. 개념과 등장 배경

1969년 미국 벨 연구소에서 켄 톰프슨(Ken Thompson)과 데니스 리치(Dennis Ritchie)가 유닉스(Unix)를 만들었다. 유닉스의 철학은 "한 가지 일을 잘하는 작은 프로그램을 만들고, 텍스트로 서로 연결하라"였고, 1973년 파이프가 도입되며 이 철학이 완성되었다. 1979년 본 셸(sh), 1989년 브라이언 폭스(Brian Fox)가 GNU 프로젝트로 만든 bash(Bourne-Again SHell)가 나왔다.

1991년 리누스 토르발스(Linus Torvalds)가 리눅스 커널을 공개했고, GNU 도구와 합쳐져 무료 유닉스 계열 운영체제가 되었다. 지금은 웹 서버, 클라우드, 슈퍼컴퓨터, 안드로이드의 기반이다. 마이크로소프트는 2006년 PowerShell을 내놓았고, 2016년 오픈소스로 공개해 리눅스·맥에서도 쓸 수 있게 했다.

## 3. 직관적 설명 및 기초 이론

### 모든 것은 파일, 모든 것은 텍스트

유닉스 계열에서는 문서뿐 아니라 장치, 설정, 프로세스 정보까지 파일처럼 다룬다. 설정은 대부분 텍스트 파일이라 편집기로 고치고, 명령 결과도 텍스트라 다른 명령이 받아 처리할 수 있다. 그래서 `grep`(찾기), `sort`(정렬), `uniq`(중복 세기), `cut`(칸 자르기), `awk`(칸 계산) 같은 작은 도구를 조합하면 간단한 데이터 처리를 할 수 있다.

### 표준 입력·출력·오류

모든 프로그램은 세 통로를 가진다: 표준 입력(0번, 키보드), 표준 출력(1번, 화면), 표준 오류(2번, 화면). 파이프는 1번을 다음 프로그램의 0번에 잇는다. 오류(2번)는 파이프로 넘어가지 않아 결과와 오류 메시지가 섞이지 않는다. `명령 > 결과.txt 2> 오류.txt`로 따로 저장할 수 있다.

### 권한 숫자 읽기

`rwxr-xr-x`를 세 글자씩 나누면 소유자 `rwx`(4+2+1=7), 그룹 `r-x`(4+0+1=5), 기타 `r-x`(5) → `755`. "주인은 읽고 쓰고 실행, 나머지는 읽고 실행만". 비밀번호가 든 설정 파일은 `600`(`rw-------`, 주인만 읽고 쓰기)으로 둔다.

## 4. 엄밀한 정의와 작동 원리

### 명령을 찾는 과정

`python`을 입력하면 셸은 (1) 별칭·내장 명령인지 보고, (2) 아니면 환경 변수 `PATH`에 적힌 폴더들을 앞에서부터 차례로 뒤져 `python`이라는 실행 파일을 찾는다. "명령을 찾을 수 없음" 오류는 대부분 `PATH`에 그 폴더가 없어서다. `which python`(bash)이나 `Get-Command python`(PowerShell)으로 어느 파일이 실행되는지 확인한다.

### 프로세스와 종료 코드

명령을 실행하면 새 프로세스가 생기고, 끝날 때 0~255의 종료 코드를 남긴다(프로세스·스레드·동시성, CS-OS-001). bash에서는 `$?`로 직전 명령의 종료 코드를 본다. `명령1 && 명령2`는 1이 성공했을 때만 2를 실행하고, `명령1 || 명령2`는 1이 실패했을 때만 2를 실행한다.

### 파이프라인의 종료 코드 함정

bash는 기본적으로 파이프라인의 **마지막** 명령 종료 코드만 본다. `false | true`의 종료 코드는 0(성공)이다. 앞 단계가 실패해도 성공으로 보이는 것이다. `set -o pipefail`을 켜면 중간 실패도 실패(1)로 잡힌다. 이 학습 사이트의 자동 실행도 테스트 결과의 종료 코드를 따로 저장해 확인한 뒤에만 커밋한다.

### 안전한 스크립트의 기본

```bash
#!/usr/bin/env bash
set -euo pipefail          # 실패하면 멈춤(-e), 없는 변수는 오류(-u), 파이프 중간 실패도 잡음
BACKUP_DIR="/backup/$(date +%F)"
mkdir -p "$BACKUP_DIR"      # 변수는 항상 큰따옴표로 감싸 공백이 있어도 안전하게
pg_dump mydb > "$BACKUP_DIR/mydb.sql"
echo "백업 완료: $BACKUP_DIR"
```

## 5. 수식 및 기호 설명

| 기호·명령 | 뜻 |
|---|---|
| `\|` | 파이프: 앞 출력 → 뒤 입력 |
| `>`, `>>` | 출력을 파일에 덮어쓰기, 이어쓰기 |
| `2>` | 오류 출력을 파일로 |
| `&&`, `\|\|` | 앞이 성공하면 / 실패하면 다음 실행 |
| `$변수`, `"$변수"` | 변수 값(큰따옴표로 감싸기 권장) |
| `$?` | 직전 명령의 종료 코드 |
| `*` | 이름 패턴(예: `*.csv`는 csv 파일 전부) |
| `chmod 755 파일` | 권한을 rwxr-xr-x로 |
| `sudo` | 관리자 권한으로 실행(주의) |

## 6. 단계별 계산 또는 동작 예제

### 예제 1. 로그에서 오류 세기

```bash
grep "ERROR" app.log | cut -d' ' -f3 | sort | uniq -c | sort -rn | head -5
```

1. `grep "ERROR" app.log`: 오류가 든 줄만 고른다.
2. `cut -d' ' -f3`: 공백으로 나눈 세 번째 칸(예: 오류 종류)만 남긴다.
3. `sort | uniq -c`: 정렬한 뒤 같은 값의 개수를 센다(`uniq`는 붙어 있는 중복만 세므로 정렬이 먼저다).
4. `sort -rn | head -5`: 개수 큰 순서로 정렬해 상위 5개.

SQL로 쓰면 `SELECT 종류, COUNT(*) FROM 로그 WHERE 내용 LIKE '%ERROR%' GROUP BY 종류 ORDER BY 2 DESC LIMIT 5`와 같은 일이다(SQL 조회·조인·집계, DE-SQL-001).

### 예제 2. CSV 칸별 합계

`s.csv`가 `a,3` / `b,5` / `a,2`일 때 `awk -F, '{s[$1]+=$2} END{for(k in s) print k,s[k]}' s.csv`는 `a 5`, `b 5`를 출력한다. 첫 칸을 키로 두 번째 칸을 더하는 `GROUP BY` 합계다. 간단한 확인에는 편하지만, 따옴표 안의 쉼표 같은 CSV 규칙은 처리하지 못하므로 실제 데이터 처리는 pandas나 DB로 한다(데이터프레임과 pandas, DE-PANDAS-001).

### 예제 3. 권한 숫자 바꾸기

`chmod 754 run.sh` → `rwxr-xr--`. 소유자 7(rwx), 그룹 5(r-x), 기타 4(r--). 아래에서 직접 계산해 보자.

### 직접 해보기

```runjs
// @title 파일 권한 숫자 ↔ rwx 글자 변환
// @label 권한 글자
// @param owner | 소유자(0~7) | 0 | 7 | 7 | 1
// @param group | 그룹(0~7) | 0 | 7 | 5 | 1
// @param other | 기타 사용자(0~7) | 0 | 7 | 5 | 1
// @expect owner=7, group=5, other=5 => rwxr-xr-x
// @expect owner=6, group=4, other=4 => rw-r--r--
// @expect owner=6, group=0, other=0 => rw-------
const toRwx = (n) => (n & 4 ? 'r' : '-') + (n & 2 ? 'w' : '-') + (n & 1 ? 'x' : '-');
const who = [['소유자', owner], ['그룹', group], ['기타', other]];
table(who.map(([w, n]) => [w, n, toRwx(n), [n & 4 ? '읽기' : '', n & 2 ? '쓰기' : '', n & 1 ? '실행' : ''].filter(Boolean).join('·') || '없음']), ['대상', '숫자', '글자', '할 수 있는 일']);
const s = who.map(([, n]) => toRwx(n)).join('');
log(`chmod ${owner}${group}${other} 파일  →  ${s}`);
if (other & 2) log('주의: 모든 사용자가 쓸 수 있습니다. 운영 서버에서는 거의 쓰지 않습니다.');
result(s);
```

### 예제 4. 파이프라인 실패 숨김

```bash
pg_dump mydb | gzip > backup.sql.gz
echo "종료 코드: $?"
```

DB 접속이 실패해 `pg_dump`가 오류를 내도, 마지막 `gzip`은 빈 입력을 압축하고 성공(0)한다. 백업 파일이 비어 있는데 "성공"으로 기록되는 것이다. `set -o pipefail`을 켜고, 백업 후 파일 크기나 복원 시험으로 확인한다.

## 7. 시각화와 해석

파이프라인은 왼쪽에서 오른쪽으로 흐르는 공장 라인으로 그리면 이해하기 쉽다. 각 상자가 명령, 화살표가 텍스트 흐름이다. 디렉터리 구조는 `tree` 명령이나 들여쓰기 목록으로 본다. 서버 상태는 `top`·`htop`(CPU·메모리 사용 프로세스), `df -h`(디스크 남은 양), `du -sh *`(폴더별 크기)로 확인하며, 정기적으로 수집해 그래프로 만들면 관측성 도구가 된다(로깅·모니터링·관측성, OPS-OBS-001).

## 8. 기술 비교 및 선택 기준

## 9. 실무 사례

- **예약 실행(cron):** `30 2 * * * /opt/scripts/backup.sh`는 매일 새벽 2시 30분에 백업한다. 다섯 칸은 분·시·일·월·요일. 윈도우에서는 작업 스케줄러가 같은 역할이다. 이 학습 사이트의 매일 갱신도 같은 형식의 일정(`44 5 * * *`, 한국 시간)으로 실행된다.
- **원격 접속(ssh):** `ssh 사용자@서버`로 화면 없는 서버에 접속해 명령을 실행한다. 비밀번호 대신 키 파일을 쓰고, 키 파일 권한은 600으로 둔다(웹 보안 기초, SE-SEC-001).
- **Git과 개발 도구:** `git`, `npm`, `pip`, `docker`가 모두 셸 명령이다(Git과 버전 관리, SE-GIT-001).
- **컨테이너와 CI:** 배포 자동화 파일(Dockerfile, CI 설정)의 각 단계는 결국 셸 명령의 나열이다(배포와 환경 분리, OPS-DEPLOY-001).

## 10. 기존 프로젝트와의 연결

아래 사실은 포트폴리오·저장소 원문(`content/profile.json`)과 DeepVi 저장소에서 확인한 것이다.

- **Preflight — 설치·백업·복원 스크립트:** PowerShell로 정리했다. 점검 질문: 스크립트가 중간 단계 실패 시 멈추는가(`$ErrorActionPreference = 'Stop'` 또는 명령별 결과 확인)? 예제 4처럼 백업이 빈 파일로 "성공"하는 경우를 막으려면, 백업 뒤 파일 크기 확인이나 주기적인 복원 시험이 필요하다(OPS-DEPLOY-001의 RTO 점검).
- **Preflight — 배포 게이트:** 개발을 거치지 않은 변경은 배포 스크립트가 거부한다. 셸 스크립트에서 조건을 검사해 0이 아닌 종료 코드로 멈추는 것이 이 게이트의 구현 방식이다. 거부 사유를 기록으로 남기면 나중에 추적하기 쉽다.
- **Preflight — 비밀값:** 사내 서버 운영 스크립트에 DB 비밀번호가 필요하다면, 스크립트 파일에 직접 쓰지 않고 권한이 제한된 별도 파일이나 환경 변수로 전달하는 것이 원칙이다. 실제 방식은 기록이 없어 점검 사항이다.
- **DeepVi — Procfile:** 내용은 `web: streamlit run app.py --server.address 0.0.0.0 --server.port $PORT` 한 줄이다. `streamlit run app.py`가 명령과 대상, `--server.port`가 옵션이고, `$PORT`는 플랫폼이 넣어 주는 **환경 변수**다. 포트 번호를 코드에 고정하지 않고 실행 환경이 정하게 한 것이다. 실행 명령이 코드와 함께 버전 관리되므로, 다른 사람이 같은 방식으로 앱을 띄울 수 있다.

## 11. 가정·한계·흔한 오해·트레이드오프

- **오해: 셸은 옛날 방식이다.** 서버·클라우드·컨테이너·CI의 기본 인터페이스이며, AI 코딩 도구도 셸 명령으로 일한다.
- **위험한 명령:** `rm -rf`는 휴지통 없이 지운다. 변수가 비어 `rm -rf "$DIR/"`가 `rm -rf /`가 되는 사고가 실제로 있다(`set -u`와 경로 확인으로 예방). `sudo`는 꼭 필요할 때만.
- **공백과 따옴표:** 파일 이름에 공백이 있으면 따옴표 없는 변수가 두 개로 쪼개진다. 변수는 항상 `"$변수"`.
- **줄바꿈 차이:** 윈도우에서 만든 스크립트(CRLF)를 리눅스에서 실행하면 이상한 오류가 난다(CS-DATA-001).
- **이식성:** bash 전용 문법은 다른 셸(sh, zsh)에서 다르게 동작할 수 있다. 첫 줄(`#!/usr/bin/env bash`)로 어느 셸인지 명시한다.

## 12. 이해 확인 및 면접 질문

<details class="qa" data-type="concept"><summary>Q1. 권한 640은 rwx 글자로 무엇이며, 누가 무엇을 할 수 있는가?</summary>

**정답.** `rw-r-----`. 소유자는 읽기·쓰기, 그룹은 읽기만, 기타 사용자는 아무것도 못 한다.

**해설.** 6 = 4+2(r, w), 4 = r, 0 = 없음. 설정 파일을 같은 팀(그룹)만 읽게 할 때 쓴다.

</details>

<details class="qa" data-type="concept"><summary>Q2. bash에서 `false | true; echo $?`의 출력과 그 이유는?</summary>

**정답.** `0`. 기본 설정에서 파이프라인의 종료 코드는 마지막 명령(true)의 것이기 때문이다. `set -o pipefail`을 켜면 `1`이 된다.

**해설.** 백업·적재 스크립트에서 앞 단계 실패가 숨는 원인이다(6절 예제 4).

</details>

<details class="qa" data-type="judgment"><summary>Q3. 운영 서버에서 매일 실행되는 정리 스크립트가 있다. 오래된 파일을 지우는 부분을 어떻게 안전하게 만들겠는가?</summary>

**정답.** `set -euo pipefail`로 실패·빈 변수에서 멈추게 하고, 지울 경로가 비어 있거나 예상 폴더가 아니면 중단하는 확인을 넣는다. 먼저 지울 목록만 출력하는 모드로 확인하고, 삭제 대신 보관 폴더로 옮긴 뒤 일정 기간 후 지우며, 실행 결과(지운 개수, 오류)를 기록하고 실패 시 알림을 보낸다.

**해설.** 되돌릴 수 없는 작업은 확인 → 기록 → 되돌릴 길 순서로 설계한다(OPS-DEPLOY-001).

</details>

<details class="qa" data-type="applied"><summary>Q4. 서버의 웹 로그(app.log)에서 오늘 가장 많이 발생한 오류 3가지를 빠르게 보려면 어떤 명령 조합을 쓰겠는가?</summary>

**정답.** 예: `grep "$(date +%F)" app.log | grep "ERROR" | cut -d' ' -f3 | sort | uniq -c | sort -rn | head -3` (오류 종류가 세 번째 칸이라고 가정). 오늘 날짜 줄 → 오류 줄 → 종류 칸 → 정렬 후 개수 → 개수순 상위 3개.

**해설.** 로그 형식(칸 구분, 날짜 형식)을 먼저 확인해야 한다. 반복해서 볼 지표라면 관측성 도구로 옮긴다(OPS-OBS-001).

</details>
