## 1. 핵심 요약

- **점근 복잡도(asymptotic complexity)**는 입력 크기 $n$이 커질 때 실행 시간이나 메모리 사용량이 **어떤 속도로 증가하는가**를 나타낸다. 절대 시간(초)이 아니라 **증가율**을 비교하는 도구다.
- $O$(Big-O)는 **상한**, $\Omega$(Big-Omega)는 **하한**, $\Theta$(Big-Theta)는 **상한과 하한이 같은 차수로 맞는 경우**다. 모두 "충분히 큰 $n$에서, 상수배를 무시하고" 성립하는 관계다.
- $O$는 "최악의 경우"와 같은 말이 아니다. 최악/평균/최선은 **어떤 입력을 볼 것인가**의 축이고, $O/\Omega/\Theta$는 **함수의 크기를 어떻게 묶을 것인가**의 축이다.
- 점근 복잡도는 상수, 캐시, 입력 분포를 숨긴다. 작은 $n$이나 실제 하드웨어에서는 $O(n^2)$ 알고리즘이 $O(n\log n)$보다 빠를 수 있다.

## 2. 개념과 등장 배경

1960년대까지 알고리즘 성능은 특정 기계에서 측정한 시간으로 비교하는 경우가 많았다. 그런데 같은 알고리즘도 CPU, 컴파일러, 언어에 따라 시간이 수 배씩 달라진다. 기계마다 달라지는 요소를 걷어내고 **알고리즘 자체의 성질**을 비교할 방법이 필요했다.

해석학에서 쓰던 Bachmann–Landau 표기법($O$, $o$)이 그 역할을 맡았다. Donald Knuth는 1976년 논문에서 컴퓨터과학에 맞게 $\Omega$와 $\Theta$의 의미를 정리해 제안했고, 이 정의가 오늘날 교재의 표준이 되었다.

핵심 아이디어는 두 가지다.

1. **상수배는 기계가 바꾼다.** 2배 빠른 CPU는 모든 알고리즘을 2배 빠르게 만든다. 따라서 상수배는 알고리즘 비교에서 제외한다.
2. **증가율은 기계가 못 바꾼다.** 입력이 10배 커질 때 $n^2$ 알고리즘은 100배 느려지고 $n\log n$ 알고리즘은 약 13배 느려진다. 이 차이는 CPU를 바꿔도 사라지지 않는다.

## 3. 직관적 설명

택배 상자 $n$개에서 특정 송장번호를 찾는 상황을 생각해 보자.

| 방법 | 행동 | 상자 수가 2배가 되면 |
|---|---|---|
| 처음부터 하나씩 확인 | 최대 $n$번 확인 | 작업량 2배 → $O(n)$ |
| 번호순으로 정렬된 선반에서 가운데부터 반씩 좁히기 | 최대 약 $\log_2 n$번 확인 | 작업량 **1번 증가** → $O(\log n)$ |
| 모든 상자 쌍을 비교해 중복 송장 찾기 | 약 $n^2/2$번 비교 | 작업량 4배 → $O(n^2)$ |

"상자 수가 2배가 되면 일이 얼마나 늘어나는가"라는 질문이 점근 복잡도의 직관이다.

## 4. 엄밀한 정의와 작동 원리

함수 $f(n)$, $g(n)$은 음이 아닌 실수값을 가진다고 하자. 여기서 $f(n)$은 알고리즘의 실제 연산 횟수, $g(n)$은 비교 기준 함수(예: $n^2$)다.

$$
f(n) = O(g(n)) \iff \exists\, c > 0,\ n_0 \ge 1 \ \text{such that}\ 0 \le f(n) \le c\,g(n)\ \ \forall n \ge n_0
$$

$$
f(n) = \Omega(g(n)) \iff \exists\, c > 0,\ n_0 \ge 1 \ \text{such that}\ 0 \le c\,g(n) \le f(n)\ \ \forall n \ge n_0
$$

$$
f(n) = \Theta(g(n)) \iff f(n) = O(g(n)) \ \text{and}\ f(n) = \Omega(g(n))
$$

정의를 읽는 법:

- **"존재한다(∃)"**: 증명할 때 $c$와 $n_0$를 **하나만 찾아 보이면** 된다.
- **"모든 $n \ge n_0$에 대해(∀)"**: 작은 $n$에서는 어긋나도 된다. 그래서 "점근적"이다.
- $=$ 기호는 관례일 뿐 등식이 아니다. 정확히는 $f(n) \in O(g(n))$, 즉 "$f$가 집합 $O(g)$에 속한다"는 뜻이다. 그래서 $n = O(n^2)$은 참이지만 $n^2 = O(n)$은 거짓이다. 좌우를 바꿀 수 없다.

### 자주 쓰는 성질

| 성질 | 내용 | 이유 |
|---|---|---|
| 상수배 무시 | $k \cdot f(n) = \Theta(f(n))$, $k>0$ | 정의의 $c$가 $k$를 흡수 |
| 합의 법칙 | $f_1 + f_2 = O(\max(g_1, g_2))$ | 큰 항이 결국 지배 |
| 곱의 법칙 | $f_1 \cdot f_2 = O(g_1 \cdot g_2)$ | 중첩 반복문 |
| 로그 밑 무관 | $\log_a n = \dfrac{\log_b n}{\log_b a}$ | 밑을 바꾸면 상수배만 달라짐 |
| 다항식 | $a_k n^k + \dots + a_0 = \Theta(n^k)$, $a_k>0$ | 최고차항이 지배 |

### 대표적인 복잡도 클래스

| 클래스 | 이름 | 대표 예 |
|---|---|---|
| $O(1)$ | 상수 | 배열 인덱스 접근, 해시 테이블 조회(평균) |
| $O(\log n)$ | 로그 | 이진 탐색, 균형 이진 탐색 트리·B-Tree 탐색 |
| $O(n)$ | 선형 | 리스트 전체 순회, 최댓값 찾기 |
| $O(n \log n)$ | 선형로그 | 병합 정렬, 힙 정렬, 비교 기반 정렬의 하한 |
| $O(n^2)$ | 이차 | 이중 반복문으로 모든 쌍 비교, 삽입 정렬(최악) |
| $O(2^n)$ | 지수 | 부분집합 전수 탐색 |
| $O(n!)$ | 팩토리얼 | 순열 전수 탐색(외판원 문제 완전 탐색) |

## 5. 수식 및 기호 설명

| 기호 | 의미 |
|---|---|
| $n$ | 입력 크기. 무엇을 $n$으로 볼지 먼저 정해야 한다(원소 수, 비트 수, 정점 수 $V$와 간선 수 $E$ 등). |
| $f(n)$ | 분석 대상 알고리즘의 비용 함수(기본 연산 횟수 또는 메모리 칸 수) |
| $c$ | 상수배를 흡수하는 양의 상수 |
| $n_0$ | "여기서부터는 항상 성립"하는 시작점 |
| $T(n)$ | 재귀 알고리즘의 실행 시간을 나타내는 점화식 |
| $o(g)$ | little-o. 모든 $c>0$에 대해 결국 $f < c\,g$. 즉 $f$가 $g$보다 **엄격히** 느리게 증가 ($\lim f/g = 0$) |

## 6. 단계별 계산 예제

### 예제 1. 정의로 증명하기: $3n^2 + 5n + 2 = \Theta(n^2)$

**상한.** $3n^2 + 5n + 2 \le 4n^2$을 만족하는 $n_0$를 찾는다. 정리하면 $n^2 - 5n - 2 \ge 0$이고, 근의 공식으로 양의 근은 $\frac{5+\sqrt{33}}{2} \approx 5.37$이다. 따라서 $c = 4,\ n_0 = 6$이면 모든 $n \ge 6$에서 성립한다. 확인: $n=6$일 때 좌변 $108+30+2 = 140$, 우변 $4 \cdot 36 = 144$.

**하한.** $n \ge 1$이면 $5n + 2 > 0$이므로 $3n^2 \le 3n^2 + 5n + 2$. 따라서 $c = 3,\ n_0 = 1$.

두 조건이 모두 성립하므로 $\Theta(n^2)$이다. $c$와 $n_0$는 유일하지 않다. $c=10, n_0=1$도 상한 증명에 쓸 수 있다.

### 예제 2. 반복문 세기

```python
def count_pairs(xs):
    count = 0
    for i in range(len(xs)):          # i = 0 .. n-1
        for j in range(i + 1, len(xs)):  # j = i+1 .. n-1
            if xs[i] == xs[j]:
                count += 1
    return count
```

안쪽 반복은 $i$마다 $n-1-i$번 돈다. 전체 비교 횟수는

$$
\sum_{i=0}^{n-1} (n-1-i) = (n-1) + (n-2) + \dots + 0 = \frac{n(n-1)}{2} = \Theta(n^2).
$$

$n=1000$이면 비교는 499,500번이다. 같은 문제를 해시 집합(set)으로 풀면 원소마다 평균 $O(1)$ 조회를 한 번씩 하므로 평균 $O(n)$이 된다.

### 예제 3. 이진 탐색의 점화식

정렬된 배열의 가운데를 보고 절반을 버린다. 비교 1회와 크기 절반의 부분 문제가 남으므로

$$
T(n) = T(n/2) + 1,\quad T(1) = 1.
$$

펼쳐 보면 $T(n) = T(n/2^k) + k$이고 $n/2^k = 1$이 되는 $k = \log_2 n$에서 멈추므로 $T(n) = \log_2 n + 1 = \Theta(\log n)$. $n = 10^9$이어도 비교는 약 30번이다.

### 예제 4. 병합 정렬의 점화식

반으로 나눠 각각 정렬(2개의 부분 문제)하고, 합치는 데 $n$에 비례하는 비용이 든다.

$$
T(n) = 2\,T(n/2) + n
$$

재귀 트리로 보면 깊이 $k$에는 크기 $n/2^k$인 문제가 $2^k$개 있고, 각 층의 병합 비용 합은 $2^k \cdot n/2^k = n$으로 일정하다. 층의 수는 $\log_2 n + 1$이므로 전체는 $n(\log_2 n + 1) = \Theta(n \log n)$이다.

일반형 $T(n) = a\,T(n/b) + f(n)$은 마스터 정리(Master theorem)로 정리된다. 핵심은 $f(n)$과 $n^{\log_b a}$ 중 어느 쪽이 더 빨리 크는지 비교하는 것이다. 병합 정렬은 $a=b=2$로 $n^{\log_2 2} = n$과 $f(n)=n$이 같은 차수라 $\Theta(n\log n)$이 된다.

### 예제 5. 분할상환 분석: 동적 배열의 append

Python `list`, Java `ArrayList`처럼 꽉 차면 용량을 늘려 복사하는 배열을 생각하자. 단순화를 위해 용량을 2배로 늘린다고 가정한다(CPython의 실제 증가율은 2배보다 작지만 기하급수적으로 늘린다는 점은 같다).

$n$번 append할 때 복사는 용량이 1, 2, 4, …, 일 때 발생하고 복사한 원소 수의 합은

$$
1 + 2 + 4 + \dots + 2^{\lfloor \log_2 n \rfloor} < 2n.
$$

따라서 $n$번의 총비용은 $n$(삽입) $+ 2n$(복사) 미만, 즉 $O(n)$이고, 한 번당 **분할상환 비용**은 $O(1)$이다. 개별 append 하나는 최악 $O(n)$일 수 있지만, 연속된 연산 전체의 평균 비용은 상수다. 이것은 입력 분포에 대한 확률적 "평균"이 아니라 **최악의 연산 순서에서도 보장되는** 평균이라는 점이 중요하다.

## 7. 공간복잡도

공간복잡도는 알고리즘이 쓰는 메모리의 증가율이다. 보통 **입력 자체를 제외한 추가 공간(auxiliary space)**을 말하는 경우가 많으므로, 어느 쪽인지 명시해야 한다.

| 알고리즘 | 시간 | 추가 공간 | 비고 |
|---|---|---|---|
| 병합 정렬(배열) | $\Theta(n\log n)$ | $\Theta(n)$ | 병합용 임시 배열 |
| 힙 정렬 | $\Theta(n\log n)$ | $O(1)$ | 제자리(in-place) |
| 퀵 정렬 | 평균 $\Theta(n\log n)$, 최악 $\Theta(n^2)$ | 평균 $O(\log n)$ | 재귀 호출 스택 |
| 재귀 피보나치(메모 없음) | $\Theta(\phi^n)$ | $\Theta(n)$ | 호출 스택 깊이 $n$ |

재귀는 코드에 배열이 없어도 **호출 스택**만큼 공간을 쓴다. 재귀 깊이가 입력에 비례하면 큰 입력에서 스택 오버플로가 날 수 있다(CPython의 기본 재귀 한도는 1000).

시간과 공간은 자주 교환된다. 메모이제이션은 공간 $O(n)$을 써서 피보나치를 지수 시간에서 $O(n)$ 시간으로 줄이고, 인덱스는 디스크 공간을 써서 조회를 $O(n)$에서 $O(\log n)$으로 줄인다.

## 8. 기술 비교 및 선택 기준

**최악·평균·최선 vs. $O/\Omega/\Theta$**

| 질문 | 축 |
|---|---|
| 어떤 입력을 기준으로 볼 것인가? | 최악(worst) / 평균(average, 입력 분포 가정 필요) / 최선(best) / 분할상환(amortized) |
| 그 비용 함수를 어떻게 묶을 것인가? | $O$(상한) / $\Omega$(하한) / $\Theta$(정확한 차수) |

그래서 "퀵 정렬의 최악 시간은 $\Theta(n^2)$", "퀵 정렬의 평균 시간은 $\Theta(n\log n)$"처럼 두 축을 함께 말하는 것이 정확하다.

**점근 복잡도만으로 결정하면 안 되는 경우**

- **$n$이 작을 때.** 상수항이 지배한다. CPython의 정렬 알고리즘인 Timsort는 짧은 구간(run)을 삽입 정렬($O(n^2)$)로 처리하고, 많은 C++ 표준 라이브러리 구현의 `std::sort`(introsort)도 작은 구간에서 삽입 정렬로 전환한다.
- **메모리 계층.** 배열 순회는 연속 메모리라 캐시 적중률이 높다. 같은 $O(n)$이라도 연결 리스트 순회는 포인터를 따라가며 캐시 미스가 잦아 수 배 느릴 수 있다.
- **입력 분포.** 해시 테이블 조회는 평균 $O(1)$이지만 충돌이 몰리면 최악 $O(n)$이다. 외부 입력을 키로 쓰는 서비스에서는 이 최악이 공격 대상이 될 수 있다.
- **I/O 비용.** 데이터베이스에서는 CPU 연산보다 디스크 페이지를 몇 번 읽는지가 지배적이다. B-Tree가 이진 탐색 트리보다 선호되는 이유가 여기에 있다(→ DE-DB-001).

## 9. 실무 사례

- **DB 조회.** 조건에 맞는 행을 인덱스 없이 찾으면 테이블 전체를 읽는 순차 스캔($O(n)$ 페이지)이다. B-Tree 인덱스가 있으면 $O(\log n)$ 단계로 해당 위치에 도달한다. 단, 결과 행이 많으면(선택도가 낮으면) 옵티마이저가 순차 스캔을 고르는 것이 더 빠를 수 있다.
- **N+1 쿼리.** 목록 $n$개를 가져온 뒤 각 항목마다 쿼리를 한 번씩 더 보내면 왕복이 $n+1$번이다. 쿼리 하나는 빨라도 네트워크 왕복이 $n$에 선형으로 늘어난다. JOIN이나 `WHERE id IN (...)`으로 묶으면 왕복이 상수 번으로 줄어든다.
- **멤버십 검사.** Python에서 `x in list`는 $O(n)$, `x in set`은 평균 $O(1)$이다. 반복문 안에서 리스트 멤버십 검사를 하면 전체가 $O(n^2)$이 되는 흔한 실수가 생긴다.
- **벡터 검색.** 임베딩 $n$개와 질의 벡터의 유사도를 모두 계산하는 완전 탐색은 차원 $d$에 대해 $O(nd)$다. 수백만 개 규모에서는 HNSW 같은 근사 최근접 탐색(ANN)으로 정확도 일부를 포기하고 탐색량을 줄인다(→ AI-RAG-001).

## 10. 기존 프로젝트와의 연결

아래는 **적용 가능성 점검 질문**이다. 실제 구현 여부나 성능 수치는 기록되어 있지 않으므로 사실로 간주하지 않는다.

- **Preflight(제조 현장 업무 자동화):** 데이터 갱신 로직에 "목록을 돌며 매번 DB를 조회"하는 패턴이 있는지 점검해 볼 수 있다. 있다면 N+1 문제의 후보다.
- **DeepVi(LLM/RAG 서비스):** 문서 수가 늘 때 검색 지연이 어떻게 증가하는지(선형인가, 로그에 가까운가)를 설명할 수 있으면 벡터 인덱스 선택 근거를 면접에서 말할 수 있다.
- **STT·보고서 자동화:** 긴 녹취를 처리할 때 비용이 녹취 길이에 선형인지, 문장 쌍 비교처럼 이차로 늘어나는 단계가 있는지 구분해 본다.

## 11. 가정·한계·흔한 오해

- **오해: "$O$는 최악의 경우다."** $O$는 상한일 뿐이다. 최선의 경우에도 상한을 말할 수 있다(삽입 정렬의 최선 시간은 $O(n)$이자 $\Theta(n)$).
- **오해: "$O(n)$이 $O(n^2)$보다 항상 빠르다."** 충분히 큰 $n$에서만 보장된다. $1000n$과 $n^2$은 $n < 1000$에서 후자가 작다.
- **오해: "$O(n^2)$인 알고리즘은 실행 시간이 정확히 $n^2$에 비례한다."** $O$는 상한이라 실제로는 $n$ 정도일 수도 있다. 정확한 차수를 말하려면 $\Theta$를 쓴다. 실무와 면접에서 "Big-O"를 사실상 $\Theta$의 의미로 쓰는 경우가 많으니 맥락을 확인한다.
- **계산 모델 가정.** 일반적인 분석은 RAM 모델(기본 연산 1회 = 상수 시간, 메모리 접근 비용 균일)을 가정한다. 매우 큰 정수 연산, 캐시·디스크 계층, 병렬성은 이 모델 밖에 있다.
- **입력 크기 정의.** 정수 $N$의 소수 판별을 "$O(\sqrt N)$이니 빠르다"고 하면 함정이다. 입력 크기는 비트 수 $b = \log_2 N$이므로 $O(\sqrt N) = O(2^{b/2})$, 즉 입력 크기에 대해 지수 시간이다.

## 12. 이해 확인 및 면접 질문

<details class="qa" data-type="concept"><summary>Q1. $n = O(n^2)$은 참인가? 그렇다면 왜 보통 "선형 시간 알고리즘"을 $O(n^2)$이라고 하지 않는가?</summary>

**정답.** 참이다. $c=1, n_0=1$이면 $n \le n^2$이 성립한다.

**해설.** $O$는 상한이라 느슨한 상한도 틀리지 않는다. 하지만 정보량이 없으므로 가장 **타이트한** 상한을 말하는 것이 관례다. 정확한 차수를 말하고 싶다면 $\Theta(n)$이라고 하는 것이 가장 정확하다.

</details>

<details class="qa" data-type="concept"><summary>Q2. 해시 테이블 조회가 $O(1)$이라는 말은 정확한가?</summary>

**정답.** "좋은 해시 함수와 적절한 적재율(load factor)을 가정한 **평균** $O(1)$"이 정확하다. 최악은 $O(n)$이다.

**해설.** 모든 키가 한 버킷에 충돌하면 체이닝 구현은 리스트를 선형 탐색한다. 재해싱(resize)은 개별 연산을 $O(n)$으로 만들지만 분할상환하면 $O(1)$이다. 즉 "평균(입력 분포)"과 "분할상환(연산 순서)"이라는 두 가지 다른 근거가 함께 들어 있다.

</details>

<details class="qa" data-type="judgment"><summary>Q3. 정렬된 데이터 10개에서 값을 찾을 때 이진 탐색 대신 선형 탐색을 쓰는 것이 합리적일 수 있는 이유는?</summary>

**정답.** $n$이 매우 작으면 점근적 차이(최대 10회 vs 4회 비교)보다 분기 예측, 캐시, 코드 단순성의 영향이 더 크다.

**해설.** 점근 분석은 $n \to \infty$에서의 비교다. 작은 $n$에서는 측정(벤치마크)이 판단 근거가 되어야 한다. 표준 라이브러리 정렬이 작은 구간에서 삽입 정렬로 전환하는 것도 같은 이유다.

</details>

<details class="qa" data-type="applied"><summary>Q4. API 응답이 느려 확인해 보니 사용자 목록 500명에 대해 각 사용자의 주문을 따로 조회하고 있었다. 복잡도 관점에서 문제를 설명하고 개선안을 제시하라.</summary>

**정답.** 쿼리 수가 $n+1$로 사용자 수에 선형으로 늘어난다(N+1 문제). JOIN 또는 `WHERE user_id IN (...)` 한 번으로 묶어 왕복 횟수를 상수로 만든다.

**해설.** 쿼리 하나의 DB 내부 비용이 인덱스로 $O(\log n)$이어도 네트워크 왕복 지연(예: 수 ms)이 $n$번 곱해진다. 개선 후에는 왕복 1~2회와 결과 크기에 비례하는 전송 비용만 남는다. 결과를 애플리케이션에서 묶을 때는 해시맵으로 그룹핑해야 다시 $O(n^2)$이 되지 않는다.

</details>

<details class="qa" data-type="concept"><summary>Q5. 동적 배열의 append가 "분할상환 $O(1)$"이라는 것과 "평균 $O(1)$"이라는 것은 무엇이 다른가?</summary>

**정답.** 분할상환은 **어떤 연산 순서에서도** $n$개 연산의 총비용이 $O(n)$임을 보장한다. 평균 시간은 **입력의 확률분포**를 가정한 기댓값이다.

**해설.** 분할상환 보장은 확률 가정이 없으므로 더 강하다. 다만 개별 연산 하나의 지연은 클 수 있어서, 실시간 시스템처럼 지연 상한이 중요한 곳에서는 미리 용량을 확보(reserve)하기도 한다.

</details>
