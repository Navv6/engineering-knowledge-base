## 0. 한눈에 보기 (입문)

### 한 줄 요약
Σ(시그마)는 **"이 규칙대로 여러 개를 다 더하라"**는 줄임 기호다. 수식이 길어 보여도 대부분은 "무엇을, 어디부터 어디까지 더하는가"만 읽으면 된다.

### 쉬운 설명
마트 영수증을 떠올려 보자. 물건이 1번, 2번, 3번… 순서로 찍혀 있고 맨 아래에 **합계**가 있다. 수학에서는 이걸 이렇게 줄여 쓴다.

- 물건값을 `x₁, x₂, x₃` 처럼 쓴다. 오른쪽 아래 작은 숫자(아래 첨자)는 **몇 번째 물건인지**를 가리키는 번호표다.
- "1번부터 마지막 n번까지 전부 더해라"를 `Σ` 하나로 쓴다. Σ 아래에는 **어디부터**(i = 1), 위에는 **어디까지**(n)를 적는다. i는 "지금 몇 번째를 보고 있나"를 나타내는 번호다.

그러니까 Σ 식을 만나면 겁먹지 말고 세 가지만 확인하면 된다.
1. 번호(i)가 **어디서 시작**하나?
2. **어디서 끝**나나?
3. 번호마다 **무엇을 더하나**?

### 내 프로젝트에서는
- **Preflight의 "세는 범위"가 바로 Σ의 시작과 끝이다.** Preflight에서 일부 실적 집계가 "지금 목록"만 세는 바람에, 행이 빠지면 지난 주 숫자까지 바뀌는 문제가 있었다. 그래서 모든 산출식에 세는 범위(지금 목록·지난 기록·원본 누적)를 적게 했다(포트폴리오 기재). Σ로 말하면 **"어떤 행들에 대해 더하는가"**를 정확히 적은 것이다. 같은 덧셈이라도 범위가 다르면 다른 숫자가 나온다.
- **STT 평가의 단어 오류율(WER)도 합으로 만든 비율이다.** WER은 "틀린 단어 수의 합 ÷ 정답 단어 수의 합"이다. 6,000개 발화를 평가할 때 **발화별 오류율을 평균**하는 방법과 **전체를 다 더한 뒤 나누는** 방법은 결과가 다를 수 있다(6절 예제 4). 포트폴리오에는 어느 방식인지 적혀 있지 않으니 확인해 두면 좋다.
- **DeepVi의 유형 분류도 합을 쓴다.** "버핏 + 린치 ≥ 5" 같은 조건은 두 점수를 더한 값을 기준과 비교한다(포트폴리오 기재).

### 먼저 알면 좋은 것
- 함수와 그래프 읽기(MATH-BASE-001): "번호를 넣으면 값이 나오는 규칙"이라는 생각

## 1. 핵심 요약

- **아래 첨자** $x_i$는 "i번째 값"이다. $i$는 번호를 담는 변수다.
- **합 기호** $\sum_{i=1}^{n} x_i$는 $x_1 + x_2 + \cdots + x_n$을 줄인 것이다. 아래는 시작, 위는 끝, 오른쪽은 더할 대상이다.
- 다른 설명집의 공식들, 즉 평균 $\frac{1}{n}\sum x_i$, 내적 $\sum a_i b_i$, 할인 누적 이득 $\sum \frac{\text{rel}_i}{\log_2(i+1)}$은 모두 같은 문법으로 읽힌다.
- $1 + 2 + \cdots + n = \frac{n(n+1)}{2}$. 이중 반복문의 횟수를 셀 때 그대로 쓰인다.
- **평균들의 평균**과 **전체 합의 비율**은 다를 수 있다. 오류율 같은 비율을 모을 때 꼭 확인해야 한다.

## 2. 개념과 등장 배경

긴 덧셈을 매번 풀어 쓰는 일은 번거롭고 실수하기 쉽다. 18세기 수학자 오일러(Leonhard Euler)가 그리스 문자 Σ(시그마, 로마자 S에 해당, "Sum"의 첫 글자)를 합의 기호로 쓰기 시작했고, 시작과 끝을 아래위에 적는 오늘날의 형태는 19세기 초 푸리에(Joseph Fourier)가 정착시켰다.

이 기호 덕분에 "몇 개든 같은 규칙으로 더한다"를 한 줄로 쓸 수 있게 되었다. 프로그래밍의 반복문(`for`)과 생각하는 방식이 똑같다. 그래서 수식을 읽는 능력과 코드를 읽는 능력은 서로 도움이 된다.

## 3. 직관적 설명 및 기초 이론

Σ 식은 **반복문 한 개**와 같다.

```python
total = 0
for i in range(1, n + 1):   # i = 1, 2, ..., n
    total += x[i]           # 번호마다 x_i 를 더함
```

| 수식의 부분 | 코드의 부분 | 읽는 법 |
|---|---|---|
| $i = 1$ (아래) | `range(1, ...)` 의 시작 | "i는 1부터" |
| $n$ (위) | `... n + 1)` 의 끝 | "n까지" |
| $x_i$ (오른쪽) | `total += x[i]` | "i번째 값을 더한다" |

번호 이름은 아무거나 써도 된다. $\sum_{i=1}^{n} x_i$와 $\sum_{k=1}^{n} x_k$는 같은 식이다. 코드에서 반복 변수 이름을 `i`에서 `k`로 바꿔도 결과가 같은 것과 같다.

## 4. 엄밀한 정의와 작동 원리

### 정의

정수 $m \le n$에 대해

$$
\sum_{i=m}^{n} a_i = a_m + a_{m+1} + \cdots + a_n
$$

이고, $m > n$이면(더할 것이 없으면) 합은 $0$으로 정한다.

### 자주 쓰는 성질

| 성질 | 식 | 말로 하면 |
|---|---|---|
| 상수 꺼내기 | $\sum_{i=1}^{n} c\,a_i = c \sum_{i=1}^{n} a_i$ | 모두 c배 한 뒤 더하나, 더한 뒤 c배 하나 같다 |
| 나눠 더하기 | $\sum (a_i + b_i) = \sum a_i + \sum b_i$ | 영수증 두 장을 합쳐도 따로 더해 합쳐도 같다 |
| 상수만 더하기 | $\sum_{i=1}^{n} c = n c$ | c를 n번 더한다 |
| 주의 | $\sum a_i b_i \ne \left(\sum a_i\right)\left(\sum b_i\right)$ | 곱의 합은 합의 곱이 아니다 |

### 1부터 n까지의 합

$$
\sum_{i=1}^{n} i = 1 + 2 + \cdots + n = \frac{n(n+1)}{2}
$$

**이유.** 같은 합을 거꾸로 한 줄 더 쓰고 위아래를 더한다.

$$
\begin{aligned}
S &= 1 + 2 + \cdots + n \\
S &= n + (n-1) + \cdots + 1 \\
2S &= (n+1) + (n+1) + \cdots + (n+1) = n(n+1)
\end{aligned}
$$

$(n+1)$이 $n$개이므로 $2S = n(n+1)$, 따라서 $S = \frac{n(n+1)}{2}$.

## 5. 수식 및 기호 설명

| 기호 | 읽는 법 | 뜻 |
|---|---|---|
| $x_i$ | "엑스 아이" | i번째 x 값 |
| $\sum_{i=1}^{n}$ | "i가 1부터 n까지 합" | 아래 시작부터 위 끝까지 더하라 |
| $\cdots$ | "중간 생략" | 같은 규칙으로 이어짐 |
| $\frac{1}{n}\sum x_i$ | "x들의 합 나누기 n" | 평균 |
| $\bar{x}$ | "엑스 바" | 평균을 짧게 쓴 이름 |
| $\prod$ | "파이(곱)" | Σ의 곱셈 버전: 전부 곱하라 |

## 6. 단계별 계산 또는 동작 예제

### 예제 1. 평균

시험 점수 $x = (70, 80, 90, 60)$, $n = 4$.

$$
\bar{x} = \frac{1}{4}\sum_{i=1}^{4} x_i = \frac{70 + 80 + 90 + 60}{4} = \frac{300}{4} = 75
$$

### 예제 2. 내적 (→ MATH-LA-001)

$\mathbf{a} = (1, 2, 2)$, $\mathbf{b} = (2, 0, 1)$.

$$
\mathbf{a}\cdot\mathbf{b} = \sum_{i=1}^{3} a_i b_i = 1\cdot2 + 2\cdot0 + 2\cdot1 = 4
$$

"같은 번호끼리 곱해서 다 더한다"가 Σ로 이렇게 짧아진다. 벡터 설명집의 예제와 같은 값이다.

### 예제 3. 반복문 횟수 (→ CS-ALG-002)

```python
for i in range(n):
    for j in range(i + 1, n):
        compare(i, j)
```

안쪽 반복은 $i$일 때 $n-1-i$번 돈다. 전체 횟수는

$$
\sum_{i=0}^{n-1}(n-1-i) = (n-1) + (n-2) + \cdots + 0 = \sum_{k=0}^{n-1} k = \frac{(n-1)n}{2}.
$$

$n = 1{,}000$이면 $\frac{999 \times 1000}{2} = 499{,}500$번이다. Big-O 설명집이 "모든 쌍 비교는 $O(n^2)$"이라고 한 근거가 이 합이다.

### 예제 4. 평균들의 평균 ≠ 전체 비율

단어 오류율(WER) = 틀린 단어 수 ÷ 정답 단어 수. 발화 두 개가 있다고 하자(설명용 숫자).

| 발화 | 정답 단어 수 $N_i$ | 틀린 단어 수 $E_i$ | 발화별 오류율 $E_i/N_i$ |
|---|---|---|---|
| 1 (짧음) | 2 | 1 | 0.50 |
| 2 (긺) | 18 | 1 | 0.056 |

- **발화별 오류율의 평균:** $\frac{0.50 + 0.056}{2} \approx 0.278$
- **전체 합의 비율:** $\frac{\sum E_i}{\sum N_i} = \frac{1 + 1}{2 + 18} = \frac{2}{20} = 0.10$

같은 데이터인데 0.278과 0.10이다. 앞의 방식은 짧은 발화 하나가 결과를 크게 흔들고, 뒤의 방식은 단어 하나하나를 똑같이 센다. 그래서 비율을 보고할 때는 **어떤 방식으로 모았는지**를 함께 적어야 비교가 된다.

## 7. 시각화와 해석

이 설명집은 그림보다 표로 따라가는 편이 이해가 쉽다. 예제 3의 합을 그림으로 생각하면, $n \times n$ 정사각형 표에서 대각선 위쪽 칸만 센 것이다. 전체 $n^2$칸 중 대각선 $n$칸을 빼고 반으로 나누면 $\frac{n^2 - n}{2} = \frac{n(n-1)}{2}$이 되어 같은 답이 나온다.

## 8. 기술 비교 및 선택 기준

| 모으는 방식 | 식 | 언제 쓰나 |
|---|---|---|
| 단순 평균(매크로 평균) | $\frac{1}{n}\sum \frac{E_i}{N_i}$ | 발화·사용자·문서 **하나하나를 똑같이** 대접하고 싶을 때 |
| 전체 비율(마이크로 평균) | $\frac{\sum E_i}{\sum N_i}$ | 단어·요청 **하나하나를 똑같이** 세고 싶을 때. 음성 인식의 표준 WER 보고는 보통 이 방식이다 |
| 가중 평균 | $\frac{\sum w_i x_i}{\sum w_i}$ | 항목마다 중요도가 다를 때 |

어느 쪽이 정답이라기보다 **질문에 맞는 쪽**을 고른다. 다만 두 방식을 섞어서 비교하면 안 된다.

## 9. 실무 사례

- **대시보드 KPI:** "이번 주 완료 건수"는 이번 주 행들에 대해 1을 더한 Σ다. 어떤 행을 포함하는지(취소 건 포함 여부, 기간 경계)가 곧 Σ의 범위다.
- **평가 지표:** 정밀도·재현율·nDCG 같은 검색 지표(AI-RAG-001)는 모두 Σ로 정의된다. 공식을 Σ 문법으로 읽을 수 있으면 논문과 문서를 훨씬 빨리 읽는다.
- **SQL:** `SUM(col)`이 Σ이고, `WHERE`가 Σ의 범위다.

## 10. 기존 프로젝트와의 연결

아래 사실은 포트폴리오(`content/profile.json`)에서 옮긴 것이다.

- **Preflight:** 일부 실적 집계가 "지금 목록"만 세어 지난 주 숫자가 바뀌던 문제를, 모든 산출식에 세는 범위(지금 목록·지난 기록·원본 누적)를 적게 해서 고쳤다. 계산식 대장의 "세는 범위"는 Σ의 아래·위 범위를 문서로 고정한 것이다.
- **STT 평가:** 지표가 WER·CER·RTF였고, KsponSpeech eval_clean 3,000개와 eval_other 3,000개로 평가했다. 6,000개 결과를 모을 때 8절의 두 방식 중 무엇을 썼는지는 포트폴리오에 적혀 있지 않다. 면접에서 WER 0.226을 말할 때 "전체 단어 기준"인지 확인하고 말하면 신뢰가 올라간다.
- **DeepVi:** 유형 분류 조건에 "버핏 + 린치 ≥ 5", "버핏 + 린치 ≤ 2"처럼 두 점수의 합이 쓰였다.

## 11. 가정·한계·흔한 오해·트레이드오프

- **오해: "Σ는 어려운 고급 수학이다."** 더하기를 줄여 쓴 것뿐이다. 길게 풀어 써 보면 대부분 초등 덧셈이다.
- **오해: "곱의 합 = 합의 곱."** $\sum a_i b_i$와 $(\sum a_i)(\sum b_i)$는 다르다. $a = (1, 2)$, $b = (3, 4)$이면 앞은 $3 + 8 = 11$, 뒤는 $3 \times 7 = 21$이다.
- **시작 번호 주의.** 수학 책은 보통 1부터, 프로그래밍은 0부터 센다. 같은 식을 옮길 때 끝 번호가 하나씩 밀리지 않는지 확인한다.
- **비율의 평균 주의.** 예제 4처럼 비율을 단순 평균하면 작은 표본이 결과를 크게 흔들 수 있다.

<details class="qa" data-type="concept"><summary>Q2. 1부터 100까지 더한 값은?</summary>

**해설.** $\frac{100 \times 101}{2} = 5{,}050$. 거꾸로 한 줄 더 써서 짝지으면 101이 100개 생기고, 그 절반이다.

</details>

<details class="qa" data-type="judgment"><summary>Q3. 사용자 10명의 클릭률을 각각 구해 평균 낸 값과, 전체 클릭 수를 전체 노출 수로 나눈 값이 크게 다르다. 왜 그럴 수 있고, 무엇을 보고할까?</summary>

**정답.** 노출 수가 사용자마다 달라서다. 노출이 적은 사용자의 극단적인 클릭률이 단순 평균을 크게 흔든다. "사용자 한 명 한 명"이 기준이면 단순 평균을, "노출 한 번 한 번"이 기준이면 전체 비율을 보고하고, 어느 방식인지 함께 적는다.

**해설.** 매크로 평균과 마이크로 평균의 차이다. 둘 중 무엇을 쓸지는 질문이 정한다.

</details>

<details class="qa" data-type="applied"><summary>Q4. 대시보드의 "주간 완료 건수"가 지난 주 값까지 바뀌는 문제가 생겼다. Σ 관점에서 원인을 어떻게 찾겠는가?</summary>

**정답.** 그 숫자가 어떤 행들에 대해 더한 값인지(Σ의 범위)를 확인한다. "지금 목록에 있는 행"만 더하고 있다면, 목록에서 빠진 과거 행이 사라지며 지난 숫자가 바뀐다. 범위를 "완료 기록이 쌓인 원본 누적"으로 고정한다.

**해설.** Preflight에서 실제로 찾아 고친 문제와 같은 구조다. 산출식마다 세는 범위를 문서로 적어 두면 재발을 막을 수 있다.

</details>
