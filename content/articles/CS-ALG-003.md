## 0. 한눈에 보기 (입문)

### 한 줄 요약
**편집 거리**는 "한 글을 다른 글로 바꾸려면 글자를 최소 몇 번 고쳐야 하나(넣기, 빼기, 바꾸기)"를 센 값이다. 이 값을 빠르게 구하는 방법이 **동적계획법**, 즉 "작은 문제의 답을 표에 적어 두고 재사용하기"다.

### 쉬운 설명
"고양이"를 "고양"으로 바꾸려면 "이"를 빼면 된다. 1번. "사과"를 "사자"로 바꾸려면 "과"를 "자"로 바꾸면 된다. 1번. 이렇게 고치는 최소 횟수가 편집 거리다.

긴 문장이면 어디를 어떻게 고쳐야 최소인지 한눈에 안 보인다. 그래서 표를 그린다. 가로에 한 단어, 세로에 다른 단어를 쓰고, 칸마다 "여기까지의 앞부분끼리 바꾸는 최소 횟수"를 적어 나간다. 각 칸은 **왼쪽, 위, 왼쪽 위 대각선 칸**만 보면 채울 수 있다. 마지막 칸이 답이다.

이것이 동적계획법의 핵심이다. 큰 문제를 작은 문제로 쪼개고, 작은 문제의 답을 한 번만 계산해 표에 적어 두고 다시 쓴다.

### 내 프로젝트에서는
- **STT 평가의 WER·CER이 바로 편집 거리다.** 포트폴리오에 기재된 STT 4종 비교의 지표 WER(단어 오류율)과 CER(문자 오류율)은 "정답 문장을 인식 결과로 바꾸는 최소 편집 횟수 ÷ 정답 길이"로 계산한다. WER은 단어 단위, CER은 글자 단위 편집 거리다. 예를 들어 Riva Streaming v2의 WER 0.3116은 "정답 단어 100개당 약 31번의 단어 편집이 필요했다"는 뜻이다.
- **정답 전처리가 숫자를 바꾼다.** STT 평가에서 정답의 특수 태그·불필요한 구두점을 지우고 텍스트를 정규화했다(포트폴리오 기재). 편집 거리는 글자 하나 차이도 1로 세기 때문에, 구두점이나 띄어쓰기를 어떻게 다루느냐가 WER을 크게 바꾼다(6절 예제 3).
- **Preflight의 행 식별 문제와도 닿아 있다.** 행 번호 대신 원본 값으로 행을 식별하도록 바꿨다(포트폴리오 기재). 원본 값에 오타나 공백 차이가 섞이면 "거의 같은 값"을 찾는 데 편집 거리를 쓸 수 있다(적용 아이디어, 사용 기록 없음).

### 먼저 알면 좋은 것

- Big-O와 시간·공간복잡도(CS-ALG-002): $O(mn)$ 읽기

## 1. 핵심 요약

- **편집 거리(레벤슈타인 거리):** 삽입, 삭제, 치환(각 비용 1)으로 문자열 $a$를 $b$로 바꾸는 최소 연산 수.
- **점화식:** $D[i][j] = \min(D[i-1][j] + 1,\ D[i][j-1] + 1,\ D[i-1][j-1] + [a_i \ne b_j])$.
- **복잡도:** 시간 $O(mn)$, 공간 $O(mn)$(거리 값만 필요하면 두 줄만 써서 $O(\min(m, n))$).
- **동적계획법의 두 조건:** 최적 부분 구조(큰 문제의 최적해가 작은 문제의 최적해로 이루어짐) + 겹치는 부분 문제.
- **역추적:** 표를 거꾸로 따라가면 어떤 편집을 했는지(정렬, alignment)도 알 수 있다. WER의 S·D·I 집계가 이것이다.
- **응용:** 음성 인식 WER·CER, 맞춤법 교정, 중복 이름 매칭, DNA 서열 비교, `diff`.

## 2. 개념과 등장 배경

1965년(영문판 1966년) 소련의 블라디미르 레벤슈타인(Vladimir Levenshtein)이 오류 정정 부호 연구에서 삽입·삭제·치환으로 정의되는 거리를 제시했다. 1974년 로버트 와그너(Robert Wagner)와 마이클 피셔(Michael Fischer)는 이 거리를 $O(mn)$ 표 채우기로 구하는 알고리즘을 "문자열 간 교정 문제"로 정리했다. 비슷한 시기 생물정보학에서는 니들먼-분쉬(1970) 알고리즘으로 DNA·단백질 서열을 정렬했는데, 같은 동적계획법 구조다.

**동적계획법**이라는 이름은 1950년대 리처드 벨먼(Richard Bellman)이 다단계 의사결정 문제를 풀며 붙였다. 여기서 "프로그래밍"은 코딩이 아니라 "계획표를 짠다"는 뜻에 가깝다.

## 3. 직관적 설명 및 기초 이론

### 표의 의미

$D[i][j]$ = "$a$의 앞 $i$글자를 $b$의 앞 $j$글자로 바꾸는 최소 편집 수".

마지막 글자에서 할 수 있는 일은 세 가지뿐이다.

| 마지막 동작 | 그 전 상태 | 비용 |
|---|---|---|
| $a_i$를 **삭제** | $a$의 앞 $i-1$글자 → $b$의 앞 $j$글자 | $D[i-1][j] + 1$ (위 칸) |
| $b_j$를 **삽입** | $a$의 앞 $i$글자 → $b$의 앞 $j-1$글자 | $D[i][j-1] + 1$ (왼쪽 칸) |
| $a_i$를 $b_j$로 **치환**(같으면 그대로) | 둘 다 앞 글자까지 | $D[i-1][j-1] + (0 \text{ 또는 } 1)$ (대각선) |

셋 중 가장 작은 것을 고르면 된다. 첫 줄과 첫 칸은 "빈 문자열에서 만들기/빈 문자열로 만들기"라서 $0, 1, 2, \dots$다.

### 왜 그냥 다 해 보면 안 되나

가능한 편집 순서를 모두 따지면 경우의 수가 기하급수적으로 늘어난다. 그런데 서로 다른 순서들이 "앞 3글자 → 앞 2글자" 같은 같은 중간 상태를 계속 지나간다. 이 중간 상태의 답을 표에 한 번만 적어 두면, 칸 수 $(m+1)(n+1)$만큼만 계산하면 된다.

## 4. 엄밀한 정의와 작동 원리

### 점화식

문자열 $a = a_1 \dots a_m$, $b = b_1 \dots b_n$에 대해

$$
D[i][0] = i, \qquad D[0][j] = j
$$

$$
D[i][j] = \min\big(D[i-1][j] + 1,\; D[i][j-1] + 1,\; D[i-1][j-1] + \delta(a_i, b_j)\big)
$$

$\delta(a_i, b_j)$는 두 글자가 같으면 0, 다르면 1이다. 답은 $D[m][n]$.

### 복잡도

칸이 $(m+1)(n+1)$개이고 칸마다 상수 시간이므로 시간 $O(mn)$. 거리 값만 필요하면 바로 윗줄만 기억하면 되므로 공간을 $O(n)$으로 줄일 수 있다. 어떤 편집을 했는지까지 알려면 표 전체(또는 선택 기록)가 필요하다.

### 거리의 성질

편집 거리는 수학적 거리의 조건을 만족한다: $d(a, b) \ge 0$, $d(a, b) = 0 \iff a = b$, $d(a, b) = d(b, a)$(삽입과 삭제가 서로 뒤집힘), 삼각부등식 $d(a, c) \le d(a, b) + d(b, c)$. 좌표 거리(MATH-BASE-004)와 같은 성질을 가진 "문자열 사이의 거리"다.

### 변형

| 변형 | 차이 | 쓰임 |
|---|---|---|
| 해밍 거리 | 길이가 같고 치환만 허용 | 오류 정정 부호 |
| 다메라우-레벤슈타인 | 인접한 두 글자 맞바꿈도 1 | 타자 오타("학교" → "교학") |
| 가중 편집 거리 | 연산·글자마다 비용 다름 | 키보드상 가까운 글자 치환은 싸게 |
| 최장 공통 부분 수열(LCS) | 삽입·삭제만 | `diff`, 버전 비교 |

## 5. 수식 및 기호 설명

| 기호 | 뜻 |
|---|---|
| $D[i][j]$ | 앞 $i$글자 → 앞 $j$글자의 최소 편집 수 |
| $\delta(a_i, b_j)$ | 같으면 0, 다르면 1 |
| $\min(\cdot)$ | 가장 작은 값 |
| $O(mn)$ | 두 길이의 곱에 비례하는 시간 |

## 6. 단계별 계산 또는 동작 예제

### 예제 1. "abc" → "yabd"

| | (빈) | y | a | b | d |
|---|---|---|---|---|---|
| **(빈)** | 0 | 1 | 2 | 3 | 4 |
| **a** | 1 | 1 | 1 | 2 | 3 |
| **b** | 2 | 2 | 2 | **1** | 2 |
| **c** | 3 | 3 | 3 | 2 | **2** |

몇 칸만 따라가 보자.

- $D[1][2]$(a → ya): 대각선 $D[0][1] = 1$에 a = a라 0을 더해 1. 왼쪽 $D[1][1] + 1 = 2$, 위 $D[0][2] + 1 = 3$. 최소 **1**(y 삽입).
- $D[2][3]$(ab → yab): 대각선 $D[1][2] = 1$, b = b라 +0 → **1**.
- $D[3][4]$(abc → yabd): 대각선 $D[2][3] + 1 = 2$(c → d 치환), 왼쪽 $D[3][3] + 1 = 3$, 위 $D[2][4] + 1 = 3$. 최소 **2**.

답 2: y 삽입 1번 + c를 d로 치환 1번. 역추적은 마지막 칸에서 "어느 이웃에서 왔는지"를 거꾸로 따라가면 된다(대각선 치환 → 대각선 일치 → 대각선 일치 → 왼쪽 삽입).

### 예제 2. 단어 단위 편집 거리 (WER 계산)

정답: "나는 / 오늘 / 학교에 / 간다" (4단어)
인식: "나 / 오늘 / 학교 / 간다 / 요" (5단어)

단어를 한 글자처럼 보고 같은 표를 채우면 거리 3이다. 정렬하면:

| 정답 | 나는 | 오늘 | 학교에 | 간다 | – |
|---|---|---|---|---|---|
| 인식 | 나 | 오늘 | 학교 | 간다 | 요 |
| 편집 | 치환 S | 일치 | 치환 S | 일치 | 삽입 I |

$$
\text{WER} = \frac{S + D + I}{N} = \frac{2 + 0 + 1}{4} = 0.75
$$

$N$은 정답 단어 수다. 삽입이 많으면 WER이 1을 넘을 수도 있다.

### 예제 3. 띄어쓰기 하나가 WER을 바꾼다

정답: "회의를 시작하겠습니다" (2단어) / 인식: "회의를 시작 하겠습니다" (3단어)

- **WER:** "시작하겠습니다" → "시작" 치환 + "하겠습니다" 삽입 = 2, $\text{WER} = 2 / 2 = 1.0$ (100%)
- **CER(공백 제외 글자 단위):** 글자가 완전히 같으므로 0

의미는 똑같은데 WER은 100%다. 한국어는 띄어쓰기가 흔들리고 조사가 붙어 단어 경계가 모호해서, 한국어 음성 인식에서는 CER을 함께 보는 경우가 많다. 예제 2도 공백을 빼고 글자 단위로 보면 "나는오늘학교에간다"(9글자) → "나오늘학교간다요"로 거리 3, CER은 약 0.33이다. 같은 결과가 WER 0.75, CER 0.33으로 크게 다르게 나온다. STT 평가에서 정답 정규화와 지표 선택을 문서로 남겨야 하는 이유다.


### 직접 해보기

치환 비용을 바꾸거나, 코드에서 두 문자열을 바꿔 표가 어떻게 채워지는지 보세요. 치환 비용을 2로 하면 "치환 1번"보다 "삭제 + 삽입"이 같은 값이 됩니다.

```runjs
// @title 편집 거리 표를 직접 채워 보기
// @label 편집 거리
// @param sub | 치환 비용 | 1 | 3 | 1 | 1
// @expect sub=1 => 2
// @expect sub=2 => 3
const a = 'abc';    // 바꿀 문자열(따옴표 안을 고쳐 보세요)
const b = 'yabd';   // 목표 문자열
const D = Array.from({ length: a.length + 1 }, (_, i) =>
  Array.from({ length: b.length + 1 }, (_, j) => (i === 0 ? j : j === 0 ? i : 0)));
for (let i = 1; i <= a.length; i++) {
  for (let j = 1; j <= b.length; j++) {
    const same = a[i - 1] === b[j - 1];
    D[i][j] = Math.min(
      D[i - 1][j] + 1,                    // 삭제(위 칸)
      D[i][j - 1] + 1,                    // 삽입(왼쪽 칸)
      D[i - 1][j - 1] + (same ? 0 : sub)  // 일치·치환(대각선)
    );
  }
}
table(D.map((row, i) => [i === 0 ? '(빈)' : a[i - 1], ...row]), ['', '(빈)', ...b]);
result(D[a.length][b.length]);
```

## 7. 시각화와 해석

편집 거리 표를 그리고 역추적 경로를 색칠하면, 왼쪽 위에서 오른쪽 아래로 가는 계단 모양 경로가 나온다. 대각선 이동은 일치·치환, 가로 이동은 삽입, 세로 이동은 삭제다. 경로가 대각선에 가까울수록 두 문자열이 비슷하다. 최단 경로 문제(MATH-GRAPH-001)로 보면, 표의 칸이 정점이고 이동이 비용 0 또는 1인 간선인 그래프에서 왼쪽 위 → 오른쪽 아래 최단 경로를 찾는 것과 같다.

## 8. 기술 비교 및 선택 기준

| 목적 | 방법 |
|---|---|
| 짧은 문자열 몇 쌍 비교 | 기본 $O(mn)$ 표 |
| 오타 교정 후보 찾기(사전 수만 개) | 편집 거리 상한을 정해 일찍 멈추기, BK-tree, 대칭 삭제 사전 |
| DB 안에서 비슷한 이름 찾기 | PostgreSQL `fuzzystrmatch`의 `levenshtein`, 또는 `pg_trgm` 유사도 + 인덱스 |
| 음성 인식 평가 | 단어/글자 단위 편집 거리 + 정렬로 S·D·I 집계(전처리 규칙 고정) |
| 의미가 같은지 판단 | 편집 거리로는 부족 → 임베딩 유사도(AI-EMB-001) |

PostgreSQL 공식 문서에 따르면 `fuzzystrmatch`의 `levenshtein`은 삽입·삭제·치환 비용을 인자로 바꿀 수 있고(생략하면 모두 1), 거리 상한을 주어 더 빨리 끝내는 `levenshtein_less_equal`도 제공한다. 입력은 각각 최대 255자다. 같은 모듈의 soundex·metaphone 계열은 UTF-8 같은 멀티바이트 인코딩에서 잘 동작하지 않으므로 한글 데이터에는 `levenshtein`을 쓰라고 안내한다.

## 9. 실무 사례

- **음성 인식·기계 번역 평가:** WER, CER, 번역의 TER가 모두 편집 거리 기반이다.
- **검색어 교정:** "postgre" → "postgres" 같은 "혹시 이것을 찾으셨나요?" 제안.
- **데이터 정제:** 거래처 이름 "(주)한국전자"와 "한국전자(주)"처럼 표기만 다른 중복 찾기(정규화 후 편집 거리).
- **코드 리뷰:** `diff`는 최장 공통 부분 수열로 바뀐 줄을 찾는다.

## 10. 기존 프로젝트와의 연결

아래 사실은 포트폴리오·저장소 원문(`content/profile.json`)에서 옮긴 것이다.

- **STT 평가 — WER·CER:** KsponSpeech eval_clean·eval_other 각 3,000개로 Faster-Whisper Medium(WER 0.5001, CER 0.2937), Riva Streaming v2(WER 0.3116, CER 0.1515) 등을 비교했다. 모든 모델에서 CER이 WER보다 낮은 것은 예제 2·3처럼 한국어의 단어 경계 문제로 단어 단위 오류가 부풀기 때문으로 해석할 수 있다(이 해석은 일반적인 경향이며 STT 보고서의 분석 기록은 아님).
- **STT 평가 — 의미 지표 추가:** WER·CER에 Semantic Similarity와 SemWER@0.85를 추가했다. 예제 3처럼 편집 거리는 의미가 같아도 높게 나올 수 있어, 의미 기반 지표로 보완한 것이다.
- **STT 평가 — 정답 정규화:** 특수 태그·불필요한 구두점 제거와 텍스트 정규화를 했다. 편집 거리는 정규화 규칙에 민감하므로, 모델 간 비교에서 같은 규칙을 적용하는 것이 공정성의 전제다.
- **Preflight — 원본 값 식별:** 행을 원본 값으로 식별한다. 원본 값에 표기 흔들림이 있다면 정확 일치 대신 편집 거리 기반 후보를 검토 대기열로 보내는 방식을 생각해 볼 수 있다(적용 아이디어).

## 11. 가정·한계·흔한 오해·트레이드오프

- **오해: 편집 거리가 작으면 의미가 비슷하다.** "가능"과 "불가능"은 거리 1이지만 정반대다. 의미는 임베딩 같은 다른 도구로 본다.
- **오해: WER은 0~1 사이다.** 삽입이 많으면 1을 넘는다.
- **길이 정규화:** 긴 문자열일수록 거리가 커지므로, 비교할 때는 길이로 나누거나 유사도로 바꾼다.
- **비용:** $O(mn)$이라 긴 문서끼리, 혹은 많은 쌍을 비교하면 느리다. 후보를 먼저 줄인다.
- **유니코드:** 한글 음절을 글자 하나로 볼지, 자모로 분해할지에 따라 거리가 달라진다("각" → "간"은 음절 단위 1, 자모 단위로도 1이지만 "가" → "각"은 자모 단위로 받침 삽입 1).

## 12. 이해 확인 및 면접 질문

<details class="qa" data-type="concept"><summary>Q1. 편집 거리 점화식의 세 항이 각각 어떤 편집에 해당하는가?</summary>

**정답.** $D[i-1][j] + 1$은 $a_i$ 삭제, $D[i][j-1] + 1$은 $b_j$ 삽입, $D[i-1][j-1] + \delta$는 치환(같으면 비용 0의 일치).

**해설.** 마지막 글자에서 가능한 동작이 이 셋뿐이라 최솟값을 고르면 된다.

</details>

<details class="qa" data-type="concept"><summary>Q2. 길이 1,000과 2,000인 문자열의 편집 거리를 기본 방법으로 구하면 대략 몇 칸을 계산하는가?</summary>

**정답.** 약 $1001 \times 2001 \approx 200$만 칸.

**해설.** 시간 $O(mn)$이다. 거리만 필요하면 메모리는 한 줄(약 2,000칸)씩만 유지하면 된다.

</details>

<details class="qa" data-type="judgment"><summary>Q3. 한국어 STT 모델 두 개를 비교하는데 WER은 A가, CER은 B가 더 좋다. 어떻게 해석하고 무엇을 확인하겠는가?</summary>

**정답.** 띄어쓰기·조사 처리 방식 차이로 단어 경계가 달라졌을 가능성이 크다. 정렬 결과에서 오류 유형(띄어쓰기만 다른 경우, 실제 단어 오인식)을 나눠 보고, 정답 정규화 규칙이 두 모델에 같게 적용됐는지 확인한다. 용도(자막, 검색, 요약)에 따라 어느 지표가 중요한지 정하고, 필요하면 의미 기반 지표도 함께 본다.

**해설.** 예제 3처럼 띄어쓰기 하나로 WER이 크게 변한다. 지표 차이의 원인을 오류 사례로 확인하는 것이 먼저다.

</details>

<details class="qa" data-type="applied"><summary>Q4. 거래처 테이블에서 표기만 다른 중복("㈜한빛전자", "한빛전자(주)", "한빛 전자")을 찾으려 한다. 어떻게 하겠는가?</summary>

**정답.** 먼저 정규화(괄호·법인 표기 제거, 공백 제거, 전각/반각 통일)를 하고, 정규화한 값끼리 정확히 같은 것을 묶는다. 남은 것은 편집 거리(또는 PostgreSQL `levenshtein`, 트라이그램 유사도)로 가까운 후보를 찾아 사람이 확인하게 한다.

**해설.** 편집 거리만으로는 "(주)" 위치 차이가 큰 거리로 잡힌다. 정규화로 쉬운 차이를 먼저 없애는 것이 효율적이다.

</details>
