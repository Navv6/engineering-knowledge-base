## 0. 한눈에 보기 (입문)

### 한 줄 요약
**과적합**은 모델이 훈련 데이터의 우연한 잡음까지 외워서, 처음 보는 데이터에서는 오히려 틀리는 현상이다. 그래서 모델은 **학습에 쓰지 않은 데이터**로 평가해야 하고, 데이터가 적으면 나눠 쓰는 일을 여러 번 돌아가며 하는 **교차검증**을 쓴다.

### 쉬운 설명
시험 공부를 생각해 보자. 기출문제의 답을 번호째 외운 학생은 기출문제를 다시 풀면 100점이지만, 숫자만 바꾼 새 문제에서는 무너진다. 원리를 이해한 학생은 기출 점수는 조금 낮아도 새 문제에서 잘한다.

- **과적합(overfitting):** 답을 외운 학생. 훈련 데이터에서는 오차가 거의 0인데 새 데이터에서 크다.
- **과소적합(underfitting):** 공부를 너무 대충 한 학생. 훈련 데이터에서도 새 데이터에서도 틀린다.
- **좋은 모델:** 둘 다에서 비슷하게 괜찮은 모델. 이를 **일반화**가 잘 됐다고 한다.

그래서 데이터를 나눈다. 공부용(**훈련 세트**), 모의고사용(**검증 세트**: 공부 방법·모델 설정 고르기), 진짜 시험(**테스트 세트**: 마지막에 한 번만). 진짜 시험지를 미리 보고 공부하면 점수가 의미 없어지듯, 테스트 데이터가 학습 과정에 조금이라도 새어 들어가면(**데이터 누수**) 평가가 부풀려진다.

데이터가 적어 모의고사를 따로 떼기 아까우면, 데이터를 5묶음으로 나눠 한 묶음씩 돌아가며 모의고사로 쓰고 나머지로 공부하는 일을 5번 반복해 평균을 낸다. 이것이 **5-겹 교차검증**이다.

### 내 프로젝트에서는
- **STT 평가 — 따로 떼어 둔 평가 데이터:** 모델 4종을 KsponSpeech **eval**_clean 3,000개 + eval_other 3,000개로 평가했다(포트폴리오 기재). 학습용과 분리해 공개된 평가용 세트를 쓴 것은 "처음 보는 데이터로 평가"하는 원칙에 맞다. 다만 Whisper-small-ko Fine-tuned처럼 **추가 학습된** 모델은 그 학습 데이터에 같은 평가 문장이 섞이지 않았는지 확인해야 공정한 비교가 된다(10절).
- **Preflight — 반례 테스트:** 품목 기준 중복 제거가 두 사출처에 나눠 맡긴 정상 데이터를 지운 사고 뒤, 판정 키를 넓히고 **반례 테스트**를 추가했다(ADR-02). 알고 있던 사례에만 맞춘 규칙이 새로운 경우에 깨진 것으로, 머신러닝 모델은 아니지만 과적합과 같은 구조다.
- **DeepVi — 테스트 프롬프트:** 테스트용 프롬프트로 답변이 보유 데이터에 근거하는지 확인했다(정량 평가 지표는 기재 없음). 같은 프롬프트로 프롬프트를 계속 고치면 그 프롬프트에만 맞춰질 수 있어, 고칠 때 쓰는 질문과 마지막 확인용 질문을 나누는 것이 좋다.

### 먼저 알면 좋은 것
- 회귀분석 기초(STAT-REG-001): 모델을 데이터에 맞추는 최소제곱
- 분류 평가 지표(AI-EVAL-001): 정확도·정밀도·재현율

## 1. 핵심 요약

- **일반화 오차:** 처음 보는 데이터에서의 오차. 진짜 목표는 이것을 줄이는 것이다.
- **과소적합 vs 과적합:** 모델이 너무 단순하면 둘 다 큰 오차(편향 큼), 너무 복잡하면 훈련 오차만 작고 새 데이터 오차는 큼(분산 큼).
- **데이터 분할:** 훈련(학습) / 검증(설정 선택) / 테스트(최종 1회 평가).
- **k-겹 교차검증:** 데이터를 $k$묶음으로 나눠 각 묶음을 한 번씩 검증에 쓰고 평균·표준편차를 낸다. 데이터가 적을 때 평가를 안정시킨다.
- **분할은 데이터 구조를 따른다:** 시계열은 과거로 학습·미래로 평가, 같은 사람·같은 기업의 데이터는 같은 묶음에(그룹 분할), 클래스 비율 유지(층화).
- **데이터 누수:** 전처리를 전체 데이터로 한 뒤 분할, 중복 데이터, 예측 시점에 알 수 없는 정보, 테스트 세트 반복 사용.
- **과적합 줄이기:** 데이터 늘리기, 단순한 모델, 규제(L1·L2), 조기 종료, 앙상블.

## 2. 개념과 등장 배경

"모델을 만든 데이터로 모델을 평가하면 낙관적"이라는 문제는 통계학에서 오래전부터 알려져 있었다. 1970년대 스톤(Stone)과 가이저(Geisser)가 교차검증을 체계화했고, 1979년 에프론(Efron)의 부트스트랩과 함께 데이터를 재사용해 예측 오차를 추정하는 표준 방법이 되었다(재표본추출과 부트스트랩, STAT-BOOT-001).

머신러닝이 확산되며 데이터 누수가 주요 실패 원인으로 떠올랐다. 2012년 Kaufman 외는 데이터 마이닝 대회와 실무에서 반복된 누수 사례를 정리했다. 최근에는 LLM 평가에서 벤치마크 문제가 학습 데이터에 섞여 들어가는 **오염(contamination)** 문제가 같은 맥락에서 논의된다(LLM 응용 평가, AI-LLMEVAL-001).

## 3. 직관적 설명 및 기초 이론

### 복잡도와 오차의 U자 곡선

모델 복잡도(다항식 차수, 나무 깊이, 신경망 크기)를 키우면

- 훈련 오차는 계속 줄어든다(외울 수 있는 능력이 커짐).
- 새 데이터 오차는 처음엔 줄다가 어느 지점부터 다시 커진다.

그 바닥 지점이 적당한 복잡도다. 6절 직접 해보기에서 다항식 차수로 확인할 수 있다.

### 편향과 분산

같은 방식으로 다른 데이터 묶음에 여러 번 학습시킨다고 상상하자.
- **편향(bias):** 평균적으로 진짜 규칙에서 얼마나 벗어나는가. 직선으로 곡선을 맞추면 데이터를 바꿔도 늘 빗나간다.
- **분산(variance):** 데이터가 조금 바뀔 때 모델이 얼마나 출렁이는가. 점 10개를 모두 지나는 9차 다항식은 점 하나만 바뀌어도 모양이 크게 변한다.

## 4. 엄밀한 정의와 작동 원리

### 편향-분산 분해

$y = f(x) + \varepsilon$ ($E[\varepsilon] = 0$, $\text{Var}(\varepsilon) = \sigma^2$)이고, 훈련 데이터에 따라 달라지는 예측 $\hat{f}(x)$에 대해, 한 점 $x$에서의 기대 제곱 오차는

$$
E\big[(y - \hat{f}(x))^2\big] = \underbrace{\big(E[\hat{f}(x)] - f(x)\big)^2}_{\text{편향}^2} + \underbrace{\text{Var}\big(\hat{f}(x)\big)}_{\text{분산}} + \underbrace{\sigma^2}_{\text{줄일 수 없는 잡음}}
$$

복잡한 모델은 편향을 줄이고 분산을 키운다. $\sigma^2$은 어떤 모델로도 줄일 수 없는 바닥이다.

### k-겹 교차검증

데이터를 $k$개 묶음 $D_1, \dots, D_k$로 나누고, $j$번째에서 $D_j$를 뺀 나머지로 학습해 $D_j$에서 오차 $e_j$를 잰다.

$$
\text{CV}_k = \frac{1}{k}\sum_{j=1}^{k} e_j
$$

$k = 5$나 $10$이 흔하다. $k = n$이면 하나씩 빼는 LOOCV다. 표준편차나 묶음별 점수를 함께 보고해 평가가 얼마나 흔들리는지 보여 준다.

### 규제

손실에 가중치 크기 벌점을 더해 모델이 과하게 꺾이지 않게 한다.

$$
L_{\text{규제}} = L + \lambda \sum_j w_j^2 \;(\text{L2, 릿지}) \qquad L + \lambda \sum_j |w_j| \;(\text{L1, 라소: 일부 가중치를 0으로})
$$

$\lambda$는 검증 세트나 교차검증으로 고른다.

### 누수의 정의

예측 시점에 실제로 알 수 없는 정보가 학습이나 평가에 들어가는 것. 평가 점수가 실제 운영 성능보다 좋게 나오는 가장 흔한 원인이다.

## 5. 수식 및 기호 설명

| 기호 | 읽기 | 뜻 |
|---|---|---|
| $f(x)$ | 에프 | 숨어 있는 진짜 규칙 |
| $\hat{f}(x)$ | 에프 햇 | 데이터로 학습한 모델 |
| $\varepsilon$, $\sigma^2$ | 엡실론, 시그마 제곱 | 잡음과 그 분산 |
| MSE | 평균제곱오차 | $\frac{1}{n}\sum (\hat{y}_i - y_i)^2$ |
| $k$ | 케이 | 교차검증 묶음 수 |
| $\lambda$ | 람다 | 규제 강도 |

## 6. 단계별 계산 또는 동작 예제

### 예제 1. 다항식 차수와 과적합

숨은 규칙 $y = \sin(2\pi x)$에 작은 잡음을 더한 훈련 점 10개와, 학습에 쓰지 않은 점 9개가 있다. 차수를 바꿔 최소제곱으로 맞추면:

| 차수 | 훈련 MSE | 처음 보는 데이터 MSE | 상태 |
|---|---|---|---|
| 1 (직선) | 0.2532 | 0.2099 | 과소적합 |
| 3 | 0.0356 | 0.0245 | 좋음 |
| 5 | 0.0112 | **0.0108** | 가장 좋음 |
| 8 | 0.0002 | 0.0633 | 과적합 시작 |
| 9 | 0.0000 | 0.1063 | 점 10개를 모두 지남(외움) |

9차 다항식은 계수가 10개라 점 10개를 정확히 지나 훈련 오차가 0이 되지만, 점 사이에서 크게 출렁여 새 데이터 오차는 5차의 약 10배다.

### 직접 해보기

```runjs
// @title 다항식 차수를 올리면 생기는 일: 훈련 오차 vs 처음 보는 데이터의 오차
// @label 처음 보는 데이터의 오차(MSE)
// @param degree | 다항식 차수 | 0 | 9 | 5 | 1
// @expect degree=1 => 0.2099
// @expect degree=5 => 0.0108
// @expect degree=9 => 0.1063
const noise = [0.12, -0.18, 0.05, 0.2, -0.1, -0.15, 0.17, -0.05, 0.1, -0.2];
const f = (x) => Math.sin(2 * Math.PI * x);              // 숨은 진짜 규칙
const train = noise.map((e, i) => { const x = i / 9; return [x, f(x) + e]; });
const test = [0.05, 0.16, 0.27, 0.38, 0.5, 0.61, 0.72, 0.83, 0.94].map((x, i) => [x, f(x) + [0.08, -0.12, 0.15, -0.06, 0.1, -0.14, 0.04, 0.11, -0.09][i]]);
// 최소제곱으로 degree차 다항식 맞추기 (정규방정식 + 가우스 소거)
const d = degree, m = d + 1;
const A = Array.from({ length: m }, () => Array(m + 1).fill(0));
train.forEach(([x, y]) => { for (let r = 0; r < m; r++) { for (let c = 0; c < m; c++) A[r][c] += x ** (r + c); A[r][m] += y * x ** r; } });
for (let c = 0; c < m; c++) {
  let p = c; for (let r = c + 1; r < m; r++) if (Math.abs(A[r][c]) > Math.abs(A[p][c])) p = r;
  [A[c], A[p]] = [A[p], A[c]];
  for (let r = 0; r < m; r++) if (r !== c) { const k = A[r][c] / A[c][c]; for (let j = c; j <= m; j++) A[r][j] -= k * A[c][j]; }
}
const w = A.map((row, i) => row[m] / row[i]);
const pred = (x) => w.reduce((s, wi, i) => s + wi * x ** i, 0);
const mse = (data) => data.reduce((s, [x, y]) => s + (pred(x) - y) ** 2, 0) / data.length;
const tr = mse(train), te = mse(test);
table([['훈련 오차(MSE)', tr.toFixed(4)], ['처음 보는 데이터 오차(MSE)', te.toFixed(4)]], ['구분', '값']);
bars(['훈련', '처음 보는 데이터'], [Number(tr.toFixed(4)), Number(te.toFixed(4))]);
result(Number(te.toFixed(4)));
```

차수를 0부터 9까지 올려 보면 훈련 오차는 계속 줄지만, 처음 보는 데이터의 오차는 5에서 바닥을 찍고 다시 커진다(U자 곡선). 오차가 0.01 아래로 내려가지 않는 것은 데이터에 섞인 잡음 때문이다($\sigma^2$).

### 예제 2. 5-겹 교차검증 계산

어떤 분류 모델의 5개 묶음 정확도가 0.80, 0.85, 0.75, 0.90, 0.80이다.

- 평균: $(0.80 + 0.85 + 0.75 + 0.90 + 0.80) / 5 = 4.10 / 5 = 0.82$.
- 편차 제곱: $0.0004, 0.0009, 0.0049, 0.0064, 0.0004$, 합 $0.013$.
- 표본 표준편차: $\sqrt{0.013 / 4} = \sqrt{0.00325} \approx 0.057$.

보고: "5-겹 교차검증 정확도 0.82 ± 0.06". 다른 모델이 0.83이라면 이 흔들림 안의 차이라 더 낫다고 말하기 어렵다.

### 예제 3. 누수 찾기

1. **전처리 누수:** 전체 데이터로 평균·표준편차를 구해 정규화한 뒤 나누면, 테스트 데이터 정보가 훈련에 섞인다. 분할 후 훈련 세트로만 계산해 테스트에 적용한다.
2. **중복:** 같은 문서가 훈련과 테스트에 모두 있으면 외운 것을 맞힌 것이 된다. 분할 전에 중복을 제거한다.
3. **미래 정보:** "다음 달 지연 여부"를 예측하는데 "실제 완료일" 칸을 입력에 넣으면 정답을 보고 맞히는 것이다.
4. **그룹 누수:** 같은 화자의 음성이 훈련·테스트에 나뉘면 목소리를 외워 성능이 부풀려진다. 화자 단위로 나눈다.

## 7. 시각화와 해석

**학습 곡선**(가로축: 학습 반복 또는 데이터 양, 세로축: 오차)에 훈련 오차와 검증 오차를 함께 그린다. 두 곡선이 모두 높고 붙어 있으면 과소적합(더 복잡한 모델 필요), 훈련만 낮고 사이가 벌어지면 과적합(데이터·규제 필요)이다. 검증 오차가 바닥을 찍고 오르기 시작하는 지점에서 멈추는 것이 **조기 종료**다(신경망과 역전파, AI-NN-001). 교차검증 결과는 묶음별 점수를 점으로 찍어 흩어짐까지 보여 준다.

## 8. 기술 비교 및 선택 기준

| 데이터 상황 | 분할 방법 | 이유 |
|---|---|---|
| 데이터가 많음(수만 이상) | 훈련/검증/테스트 한 번 분할 | 충분히 안정적, 계산 저렴 |
| 데이터가 적음 | k-겹 교차검증(5, 10) | 모든 데이터를 평가에 활용, 흔들림 추정 |
| 클래스 불균형 | 층화 k-겹 | 묶음마다 양성 비율 유지 |
| 시계열(주가, 업무 기록) | 시간 순 분할, 롤링 검증 | 과거로 학습해 미래를 예측하는 실제 상황 재현 |
| 같은 대상의 여러 행(사람, 기업, 화자) | 그룹 k-겹 | 같은 대상이 양쪽에 나뉘는 누수 방지 |
| 설정 선택 + 최종 평가 모두 필요 | 중첩 교차검증 | 선택 과정의 낙관 편향 제거 |

## 9. 실무 사례

- **표준 벤치마크:** 음성 인식·이미지 인식 분야는 공식 평가 세트를 따로 두고, 그 세트로 학습하지 않는 것을 규칙으로 한다.
- **LLM 평가 오염:** 공개 벤치마크 문제가 웹에 퍼져 학습 데이터에 들어가면 점수가 부풀려진다. 사내 평가는 비공개 질문 세트를 따로 유지하고 주기적으로 새로 만든다(AI-LLMEVAL-001).
- **프롬프트 과적합:** 같은 예시 질문 몇 개로 프롬프트를 계속 고치면 그 질문에만 맞춰진다. 개발용 질문과 확인용 질문을 나눈다(프롬프트 설계와 구조화 출력, AI-PROMPT-001).
- **규칙 기반 시스템:** 알려진 사례만으로 만든 판정 규칙도 새 사례에서 깨진다. 반례 테스트와 운영 데이터 표본 점검이 검증 세트 역할을 한다(소프트웨어 테스트와 유지보수, SE-TEST-001).

## 10. 기존 프로젝트와의 연결

아래 사실은 포트폴리오·저장소 원문(`content/profile.json`)에서 옮긴 것이다.

- **STT — 평가 세트와 미세조정 모델:** KsponSpeech eval_clean·eval_other 6,000개로 4종을 평가했고, Whisper-small-ko Fine-tuned가 WER 0.239로 범용 Faster-Whisper Medium(0.5001)보다 낮았다. 점검 질문: 이 미세조정 모델의 학습 데이터에 KsponSpeech 평가 문장이나 같은 화자가 포함되었는가? 공개 미세조정 모델은 학습 데이터 구성을 모델 카드에서 확인해야 한다. 포함되었다면 비교가 그 모델에 유리하다.
- **STT — 현장 일반화:** 공개 평가 세트 성능이 실제 사용 환경(다른 마이크, 다른 연령대 화자)에서도 유지되는지는 별개 문제다. 현장 표본을 따로 모아 확인하는 것이 일반화 점검이다.
- **Preflight — 반례 테스트(ADR-02):** 품목 기준 중복 제거가 정상 데이터를 지운 사고 뒤 판정 키에 워크센터를 넣고 반례 테스트를 추가했다. 업무 규칙 단위 시험 704개와 실제 DB 점검 64개를 둔다. 알려진 사례(훈련)에만 맞춘 규칙을 새 사례(검증)로 점검하는 구조다.
- **DeepVi — 유형 분류 기준:** 버핏·린치 관점 점수로 5가지 유형을 나눴다(예: 버핏 ≥ 4 & 린치 ≤ 1). 점검 질문: 기준값을 444개 기업 전체를 보며 정했다면, 다른 시점의 데이터에서도 유형 분포와 의미가 유지되는지 확인했는가? 기준을 정한 데이터와 확인하는 데이터를 시점으로 나누면 시계열 분할이 된다.

## 11. 가정·한계·흔한 오해·트레이드오프

- **오해: 훈련 정확도가 높으면 좋은 모델.** 새 데이터 성능만이 의미 있다.
- **오해: 교차검증을 하면 누수가 없다.** 전처리를 분할 전에 하면 교차검증 안에서도 누수가 난다. 전처리를 학습 과정(파이프라인) 안에 넣는다.
- **오해: 시계열도 무작위로 섞어 나누면 된다.** 미래 데이터로 과거를 맞히는 셈이 되어 성능이 부풀려진다.
- **데이터 분포 변화:** 검증을 제대로 해도 운영 중 데이터가 바뀌면(새 품목, 새 업무 방식) 성능이 떨어진다. 운영 지표를 계속 관찰한다(로깅·모니터링·관측성, OPS-OBS-001).
- **트레이드오프:** k를 키우면 평가가 덜 치우치지만 계산이 늘고, 묶음별 점수의 분산이 커질 수 있다.

<details class="qa" data-type="judgment"><summary>Q3. 기업 444곳의 5년치 재무 데이터로 "다음 해 실적 악화"를 예측하는 모델을 만든다. 데이터를 어떻게 나누어 평가하겠는가?</summary>

**정답.** 누수 여부를 먼저 본다: 훈련·테스트 사이 중복, 분할 전 전처리, 정답이나 미래 정보가 담긴 입력 칸, 같은 대상(사람·기업·화자)이 양쪽에 있는지. 테스트 세트를 모델 선택에 반복 사용했는지 확인하고, 새로 모은 데이터나 최근 기간 데이터로 다시 평가한다. 기존 모델과 같은 테스트 세트·같은 지표인지도 확인한다.

**해설.** 갑작스러운 큰 개선은 누수의 대표 증상이다(Kaufman 외 2012).

</details>
